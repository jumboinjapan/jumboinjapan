# Страницы выбора тура

Поверхности: `/city-tour`, `/intercity`, `/multi-day`.
Режим: Persuade — помочь выбрать формат поездки и перейти к личному обсуждению.

## Общий дизайн-код

Сохраняем публичную палитру: тёплый фон `--bg`, тёмно-коричневый текст,
терракотовые действия `--accent`, спокойные подписи `--gold-text`.
Lora используется только для h1/h2; Geist — для текста, карточек и навигации.
Админка и подробные страницы маршрутов не входят в эту поверхность.

Единая последовательность: фото с заголовком и коротким описанием,
навигация между тремя форматами, маршруты, транспорт, личное обсуждение.
Контейнер 72rem с внутренними полями 24px, на телефоне 20px.
Вертикальный шаг разделов 56–96px. У каждой страницы один h1.

Обложки используют существующие фотографии, общий размер и положение текста.
Текст виден сразу, без анимации появления. Тёмный фон сохраняет читаемость
до загрузки фотографии. Ссылка «Смотреть маршруты» ведёт к списку на странице.

Карточки маршрутов: фотография 4:3, длительность, название, короткое описание,
ссылка «Посмотреть маршрут». Без теней, внешней рамки и обрезки текста.
Сетка: одна колонка до 640px, две до 1024px, три на широком экране.
Параметры многодневного маршрута остаются под описанием: старт, охват,
транспорт. Длительность находится на том же месте, что у однодневных туров.

Транспорт повторяет сетку маршрутов: три колонки на компьютере, две на
планшете, одна на телефоне; ширины и отступы общие. Фотографии 16:10 немного
ниже основных 4:3, заголовки 20px немного меньше заголовков маршрутов.
Вся карточка ведёт на подробную страницу. Отдельных широких рядов нет.
Завершение одинаковое: «Ваша поездка, ваш ритм» и переход на `/contact`.
В многодневном разделе дополнительно остаётся `/multi-day/custom`.

## Редакционные правила

Перед маршрутами один короткий абзац, помогающий выбрать. Не дублировать
описания карточек в отдельной таблице советов. Не добавлять длинные SEO-тексты,
списки преимуществ без доказательств, цены-заглушки или механику магазина.
Описание транспорта можно сокращать на фасаде: подробности доступны по ссылке.
Условия и ограничения сохраняются по смыслу.

## Реализация и границы

- `TourCollection.tsx` — обложка, навигация, секции, транспорт и контакт.
- `TourCollection.module.css` — локальные правила общего оформления.
- `TourRouteCard.tsx` — одна карточка для всех трёх разделов.
- `ExperienceCard` и `MultiDayRouteCard` адаптируют существующие контракты.
- `TransportCard` использует новый вид только с `variant="collection"`.
- `buildTourCollectionMetadata` согласует title, description, Open Graph
  и Twitter с конкретной страницей, сохраняя её canonical.

Не менять при визуальной правке загрузку Airtable, статус публикации,
дедупликацию обложек, revalidate, URL маршрутов, редиректы, формы и аналитику.
Существующие TouristTrip/CollectionPage и ссылки на сущность гида сохранены.
Ключевые сведения доступны в серверном HTML. Превью социальных сетей имеют
собственные заголовки и фото; общие Twitter-метаданные главной не наследуются.

## Проверка перед выпуском

Все три страницы на 320, 390, 768 и 1280px: отсутствие горизонтальной
прокрутки, читаемость названий, переходы карточек, навигация, якоря и контакт.
Проверить один h1, canonical, Open Graph/Twitter, JSON-LD и URL карточек.
Проверить многодневные карточки из конструктора отдельно от статических:
локальный режим без ключей показывает только статические маршруты.
Требуемая проверка репозитория — `npm run verify`; пропуски живых проверок
без ключей должны быть явно отражены в отчёте.
