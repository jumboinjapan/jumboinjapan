# Обложки туров: альбомный разворот

Шапки разделов «По Токио» и «Из Токио» используют общий `TourAlbumCover`:
17 существующих туров, два каталога и динамические страницы этих разделов.
Индивидуальная шапка Хаконе также заменена общим компонентом. Многодневные
туры в эту правку не входят.

На экране от 900 px текст и фотография стоят рядом в пропорции 45:55.
Контейнер ограничен 1280 px, поэтому широкий монитор не превращает фотографию
в узкую панораму. Изображение показано целиком с естественными пропорциями,
высотой не более 560 px. Пустое поле фотографии сохраняет плейсхолдер 3:2.
Старые настройки точки кадрирования больше не обрезают обложку.

Слева остаются название, короткий подзаголовок, продолжительность и нативное
раскрытие «О маршруте» с полным вводным текстом. Справа — фотография, подпись
и ссылка на программу. На узком экране это одна колонка: текст, фото, программа.
Фотографии остановок, данные конструктора, формы, контакты и структура
программы не менялись. Записей в Airtable нет.

## Проверки

- Все 19 страниц: HTTP 200; H1, canonical и JSON-LD совпали с предыдущей версией.
- Все 19 шапок на ширине 320 px: одна колонка, горизонтального переполнения нет.
- 1920 px: «Токио. Первый день» и Хаконе; фотографии целиком, башня от основания
  до шпиля. 1024 px: «Другой Токио», включая фотографию 5:4. 390 px: Хаконе.
- Раскрытие «О маршруте» работает с клавиатуры и сохраняет полный текст.
- TypeScript и `git diff --check` прошли.
- `npm run verify` завершился с кодом 0 (`tmp/album-spread-verify.log`).
  Проверки живой базы пропущены из-за отсутствия ключей в рабочей копии.
- Сборка Vercel успешна. Каталоги и проверенные страницы туров вернули HTTP 200.
  На опубликованной версии проверены разворот «Первого дня» при 1920 px,
  мобильная шапка Хаконе и раскрытие полного текста с клавиатуры.

В HTML изображения резервируется стандартное соотношение 3:2; после загрузки
источники других пропорций занимают естественную высоту. Это сохраняет кадр,
но у таких снимков возможно небольшое смещение макета при первой загрузке.

## Раскрытие описания

Фотография закреплена верхним краем на уровне H1. Надпись «Индивидуальные
экскурсии» вынесена в отдельную строку сетки, поэтому заголовок и фото начинают
следующую строку вместе, без вычисляемых отступов. При раскрытии описания снимок
не перемещается; прежнее центрирование по высоте отменено. Вместо плюса используется
стрелка вниз/вверх. Нативный `details` сохранён: текст доступен без JavaScript,
управление работает мышью и клавишами Enter/Space.

В поддерживающих браузерах высота раскрытия плавно меняется за 280 мс через
`::details-content` и `interpolate-size`. В остальных остаётся обычное раскрытие;
при `prefers-reduced-motion` анимация отключена.

Проверены Фудзи при 1920 px, длинное описание Хаконе при 1024 px и раскрытие
при 390 px. При открытии описания смещение снимка на десктопе равно 0 px;
на телефоне фото следует за текстом, горизонтального переполнения нет.

`npm run verify` прошёл с кодом 0 (`tmp/album-intro-verify.log`); живые проверки
без ключей пропущены. На Vercel повторно проверены раскрытие, загрузка снимка
и прежнее центрирование. Локальный dev-предпросмотр обновлён на порту 3101.

состоянии верх снимка и H1 находится на одной координате, смещение равно 0 px.
Полный `npm run verify` прошёл с кодом 0 (`tmp/album-anchor-verify.log`),
