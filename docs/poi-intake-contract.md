# Контракт приёма POI

**Действует с 6 августа 2026.** Единственный способ завести точку в базе.

---

## Правило

Ни один путь не пишет в таблицу POI напрямую. Telegram-бот, коллектор с порталов, админка, внешние агенты (LLoyd, Verter, Johny, Mason, Porter) и всё, что появится потом, вызывают `ingestPoi()` из `src/lib/poi-ingest.ts`.

Причина конкретная. До этого путей записи было три, и каждый проверял своё: агент искал дубли и **игнорировал результат** (`created: true` возвращалось всегда), заглушки из списка мест создавались вообще без проверок, админка не проверяла ничего. На живой базе это дало шесть пар дублей, четыре из которых были опубликованы.

---

## Конвейер

```
источник → КАНОН → идемпотентность → ГЕЙТ → запись черновиком
```

**1. Канон** (`poi-canon.ts`). Слаг города приводится к каноническому, типографика к «ёлочкам» и короткому тире, часы к `09:00–17:00`, категории фильтруются по белому списку из 17 значений, координаты проверяются рамкой Японии. Ошибки останавливают приём: пустое имя, отсутствие города, латиница в часах работы, запрещённые каноном слова, точка вне Японии.

**1а. Описание — только парой.** Русский текст без английского канон не принимает. Замер на живой базе 6 августа: 121 запись из 431 с русским описанием и без единого английского, обратных случаев — **ноль** во всех четырёх парах полей. Односторонний перекос означал не случайные пропуски, а незакрытый путь: исследователь возвращал английский текст, а запись его молча теряла.

Это ошибка, а не замечание: предупреждение такой долг только фиксирует. Заведению служебных записей правило не мешает — у заглушек описания нет вовсе, пояснение к ним идёт в примечания. Правку существующих текстов оно не трогает: конвейер отвечает только за заведение.

> Английский текст **не** прогоняется через русскую типографику: `canonicalText` ставит «ёлочки» и меняет точку на запятую в дробях — для английского это порча, а не канон.

**2. Идемпотентность.** Если у источника есть `externalKey`, ищется запись с тем же `Source Key`. Найдена — возвращается `already_ingested`, ничего не создаётся. Без этого второй прогон коллектора завёл бы всё заново.

**3. Гейт** (`poi-matching.ts`). Поиск дублей и родителя по всей базе — по именам и по расстоянию. Уверенный дубль в том же городе останавливает приём и возвращает ID существующей записи. Пограничные случаи пропускаются, но фиксируются в `Notes` самой записи — отчёт агента прокрутится, поле останется.

**4. Запись.** Всегда черновик: `Copy Status = Draft`, `Fact Check Status = Todo`, текст **только** в `Description Draft (RU)`.

> `Description (RU)` и `Description Approved (RU)` конвейер не заполняет никогда. Сайт рендерит `approvedRu` первым и без оглядки на `Copy Status`, поэтому запись в эти поля означала бы мгновенную публикацию непроверенного текста.

## Две оси гейта: имена и расстояние

Сравнение имён имеет предел, и он известен. Между алфавитами оно сводится к цепочке допущений — транслитерация по Поливанову, снятие родовых слов, схлопывание долгих гласных, — поэтому результат намеренно ограничен **0,85** и сам по себе не блокирует никогда. Внутри латиницы предел другой: родовое слово стоит в конце («Todai-ji Temple»), и правило «родовое отдельно от ядра» до 6 августа для английских названий не работало вовсе.

Координаты — независимая ось, и она работает в обе стороны:

| Расстояние | Что делает |
|---|---|
| ≤ 150 м при совпадении имён от 0,72 | **блокирует** — межалфавитная пара, которую имена поднять не могли |
| > 2 км | **снимает блокировку** — это тёзка, а не дубль |
| ≤ 60 м при непохожих именах | показывает соседей в `Notes`, не блокирует |

Опровержение важнее подтверждения. Совпадение имён при двух километрах между точками — тёзка: «Храм Дзёдзёдзи» есть в каждой второй префектуре, а слаг города не спасает, потому что Токио — один слаг на сорок километров. Ложная блокировка мешает завести законную точку, и владелец начинает обходить гейт силой.

**Координаты не выдумываются.** Telegram-путь их не передаёт: исследователь — языковая модель, широту и долготу она выдаст охотно и правдоподобно, а проверить нечем. Координаты приходят из структурных источников (Wikidata, OSM, BODIK), где они поле записи, а не пересказ.

## Как вызывать

```ts
import { ingestPoi } from '@/lib/poi-ingest'

const result = await ingestPoi(
  {
    source: {
      kind: 'external-agent',        // telegram-agent | portal-collector | admin | external-agent | manual-import
      id: 'johny',                   // конкретный источник
      externalKey: 'bodik:OSAKA123', // ключ В ИСТОЧНИКЕ — даёт идемпотентность
      url: 'https://...',            // первоисточник, куда идти проверять
    },
    poi: {
      nameRu: 'Храм Гокуракудзи',
      nameEn: 'Gokuraku-ji Temple',
      siteCity: 'kamakura',
      categoriesRu: ['Буддийский храм'],
      workingHours: '09:00–17:00',
      descriptionRu: '…',
      lat: 35.3163,                  // только парой и только из структурного источника
      lon: 139.5301,
      parentNameRu: 'Храм Тодайдзи',  // если объект внутри другого
    },
  },
  store,
)
```

Ответ — всегда один из пяти исходов:

| `outcome` | Что произошло |
|---|---|
| `created` | Запись создана черновиком. `poiId` и `recordId` заполнены |
| `needs_review` | Сущность неоднозначна, запись **не создана**. Причины — в `screen.reasons` и `explanation`, `poiId`/`recordId`/`fields` равны `null` |
| `blocked_duplicate` | Уже есть в базе. `poiId` — существующая запись |
| `already_ingested` | Эта запись источника уже принималась (по `Source Key`) |
| `rejected_canon` | Не прошла канон. Что именно — в `canonIssues` |

**`needs_review` появился 11.08.2026 и закрыл fail-open.** До этого дня `screenNewPoi()` возвращал такой вердикт, а `ingestPoi()` всё равно создавал запись и дописывал причину строкой в `Notes`. Сомнение не останавливало приём, а превращалось в примечание рядом с уже заведённым POI — найти такие записи в базе было нельзя, они неотличимы от прочих. Регрессионный тест закреплял именно это поведение: он ждал `created` там, где вердикт был `needs_review`.

Приём останавливают три ветки: совпадение выше порога блокировки при разных городах; совпадение в серой зоне 0,72–0,9 (сюда же попадает межалфавитная пара без координат — имена дают 0,85, решить нечем); непохожие имена в пределах 60 м.

Четвёртая ветка — «имена совпали, но между точками больше 2 км» — приём **не останавливает**. Координаты там неоднозначность снимают, а не создают, и спрашивать человека значило бы спрашивать о том, на что ответ уже получен. Пара уходит в `screen.geoRefutedDuplicate` и строкой «ТЁЗКА (расстояние сняло дубль)» в `Notes`. Замер 11.08.2026 на живой базе: ветка давала 22 остановки из 56, и все 22 — законные разные объекты («Жёлтая тыква» и «Красная тыква» Кусамы в 2,3 км, Тодайдзи и Тосёдайдзи в 5,2 км, Риннодзи в Сэндае и Риннодзи в Никко в 203 км, замок Нидзё и рынок Нидзё в 1017 км). Ни одного случая ошибочных координат.

`force: true` проходит поверх `needs_review` так же, как поверх `blocked_duplicate` — это осознанное подтверждение владельца, а не значение по умолчанию.

Поле `explanation` содержит человекочитаемое объяснение — его можно отдавать в ответ агенту или в чат без обработки.

**Пакет:** `ingestPoiBatch()` делает один снимок базы на весь пакет и проверяет каждую следующую запись против уже принятых в этом же прогоне — включая их координаты. Без этого список мест с внутренним повтором заводил дубли сам в себя.

**Предпросмотр:** `{ dryRun: true }` проходит все проверки и возвращает готовые поля, ничего не записывая. Пакетным источникам стоит показывать сводку до записи.

**Принудительно:** `{ force: true }` заводит запись поверх найденного дубля. Только по осознанному подтверждению владельца — в `Notes` это отмечается.

## Поля происхождения и координат

Добавлены в таблицу POI 6 августа 2026:

| Поле | Что хранит |
|---|---|
| `Source Key` | `<источник>:<внешний id>` — ключ идемпотентности |
| `Seed Source` | Вид источника, позволяет отобрать «всё от X» для ревизии или отката |
| `Last Seeded At` | Когда запись пришла из источника. Не дата сверки фактов |
| `Latitude` | Широта WGS 84, семь знаков. Заполняется только вместе с `Longitude` |
| `Longitude` | Долгота WGS 84, семь знаков |

Добавлены 10 августа 2026:

| Поле | Что хранит |
|---|---|
| `Google Place ID` | Идентификатор места у Google. Хранится **бессрочно** — условия Maps Platform это разрешают, в отличие от остального содержимого |
| `Coords Checked At` | Когда координаты сверялись. Крон обновляет их раз в 25 дней: у содержимого Google срок годности тридцать |
| `Operating Status` | Работает / Сезонный / Закрыт временно / Закрыт навсегда / Не проверено |
| `Season Window` | Окно сезона «ММ-ДД–ММ-ДД» без года. Осмысленно только при статусе «Сезонный» |
| `Name (JA)` | Японское имя. Берётся из **Wikidata** (CC0), а не у Google: это ключ сверки дублей, он обязан быть постоянным |
| `Wikidata QID` | Идентификатор в Wikidata |
| `Text Source` | Откуда взят текст описания: переписано с источника / написано по фактам / написано человеком / сочинено без вводных / требует проверки. Пусто = неизвестно |

Заполняются автоматически, руками не трогать.

### Разрешение места при приёме

`resolvePlace()` из `src/lib/place-resolve.ts` — единственный путь опознания.
Свои скрипты опознания писать **нельзя**: за один день 10.08.2026 три
самодельных прогона дали три ошибки, которых модуль не допускает — кафе
вместо холмов, дворец за 687 км, работа с другого острова.

Гейт опознания: рамка Японии → **сверка имени** → префектура, если она
известна. Имя сверяется ВСЕГДА, в том числе когда география сходится:
«Numa-no-Daira Plateau» иначе принимает «Daisetsuzan National Park» — та же
префектура, двадцать два километра, обе геометрические проверки проходят.

Неудача опознания приём НЕ останавливает. Запись без `place_id` хуже записи
с `place_id`, но лучше отсутствия записи; причина уходит в `openQuestions`.

### Один `place_id` — один POI

Проверка стоит в `ingestPoi` ОТДЕЛЬНО от матчера имён, потому что это
тождество, а не сходство. Имена могут расходиться сколь угодно — «Мыс
Сирэтоко» и «Круиз к мысу Сирэтоко» — но если Google считает их одним
местом, в базе им место одно. Так это и нашлось: мыс и круиз делили
`place_id` и взаимно подтверждали координаты друг друга.

Пустой `place_id` не блокирует: у части базы его нет, и блокировка по
пустому значению склеила бы всё неопознанное. `force` — осознанное решение
владельца, не путь по умолчанию.

### Статус работы и запрет на закрытые точки

`checkProgrammeUsable()` в `poi-canon.ts` — ЕДИНСТВЕННОЕ место, где решается,
можно ли ставить точку в программу. Дублировать правило в агентах нельзя.

«Сезонный» — не разновидность закрытого. Google не различает межсезонье и
закрытие: сад слив в Судзуке одиннадцать месяцев в году отдаётся как
`CLOSED_TEMPORARILY`. `operatingStatusFromGoogle()` сезонность не затирает.

Закрытую точку завести в базу МОЖНО и нужно: `applyCanon` даёт `warn`, а не
`error`. Запрет на запись означал бы, что база не помнит о закрытии, и
коллектор заведёт объект заново как незнакомый.

«Работает» исследователем не ставится — только сверкой с Google.
`parseResearchJson` подрезает это значение из ответа модели: закрытие модель
читает с таблички, а «работает» выводит из того, что обратного не нашлось.

## Что осталось за пределами контракта

- **Удаление** — `deleteAirtablePoi` по-прежнему не проверяет ссылок. Перед слиянием дублей смотрите `npm run check:poi`.
- **Правка существующих записей** идёт мимо конвейера: он отвечает только за заведение.
- ~~**Обратное заполнение координат**~~ — закрыто 10.08.2026: координаты у 415 записей из 432, гейт работает по расстоянию против 96% базы.
- **Текст при заведении.** Генератор умеет одно действие — переписать вводные, и при пустой записи выдаёт правдоподобный вымысел. С 10.08.2026 он отказывается работать без материала (422, `no_source_material`). Для записей, заводимых по фактам без исходной прозы, нужен второй режим — «написать по фактам»; его пока нет.

## Проверки

```bash
npm run test:poi-matching   # 49 проверок сопоставления имён и расстояний
npm run test:poi-ingest     # 34 проверки конвейера
npm run check:poi           # целостность живой базы, включая координаты
```

Калибровка гейта на снимке живой базы (431 запись, 6 августа): **2 блокировки** — обе настоящие пары дублей, уже слитые, — и 54 записи на проверку. Ложных блокировок нет.

**Замер 11.08.2026** — каждая из 466 записей подана в гейт как новая, против остальных 465:

| исход | записей | доля |
|---|---|---|
| `clear` | 425 | 91,2% |
| `needs_review` | 34 | 7,3% |
| `blocked_duplicate` | 7 | 1,5% |

Из 34 остановок: 21 — серая зона совпадения («Дом-проект: Хайся» против «Гокайсё»), 13 — сосед в пределах 60 м (храмовые комплексы, сад Кокинга и маяк на Эносиме в нуле метров). До возврата ветки «расстояние опровергает дубль» в разряд флага остановок было 56 (12%), и 22 из них ложные.

Замер на живой базе — нижняя оценка: у кандидатов портала координат часто нет вовсе, и доля серой зоны там будет выше. Фактическую долю измеряет прогон коллектора вхолостую до включения fail-closed в production.
