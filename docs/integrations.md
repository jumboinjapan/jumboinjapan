# Внешние API: дэшборд, сейф и процедура подключения

Страница `/admin/integrations` — единственное место, где видно состояние всех
внешних сервисов сайта: провайдеров моделей, базовой обвязки и песочницы.

## Как это устроено

Три файла, остальное производное:

| Файл | Роль |
| --- | --- |
| `src/lib/integrations/registry.ts` | Реестр: что за API, какие поля входа, чем проверять |
| `src/lib/integrations/vault.ts` | Сейф: чтение и запись учётных данных, приоритет окружения |
| `src/lib/integrations/probes.ts` | Живые проверки: жив ли ключ, какие модели доступны |

Интерфейс (`IntegrationsWorkspace.tsx`) и роуты (`/api/admin/integrations/**`)
целиком строятся из реестра. Поэтому новый API — это одна запись в реестре, а
не новая страница.

## Где лежат ключи

**Провайдеры моделей и Magic Box** — в Airtable, таблица `Integrations`, поле
`Secrets`, зашифрованные AES-256-GCM. Мастер-ключ `INTEGRATIONS_SECRET` живёт в
переменных окружения Vercel и в Airtable не попадает: выгрузка базы даёт
шифротекст, а не ключи. Ключ шифрования выводится HKDF отдельно для каждого
провайдера, так что подставить чужой блоб в чужую строку нельзя.

**Базовые сервисы** (Airtable, Telegram, Google OAuth, reCAPTCHA) — только
переменные окружения, флаг `envOnly: true` в реестре. Причины конкретные:

- Airtable — сам сейф лежит в Airtable, хранить его ключ там же рекурсивно;
- Google OAuth — `ADMIN_AUTH_SECRET` читает `proxy.ts` на edge, до всякого
  Airtable;
- Telegram и reCAPTCHA — работают в публичных роутах, где лишний поход в
  Airtable на каждый запрос это и задержка, и точка отказа.

**Переменная окружения всегда важнее сейфа.** Если задан `OPENAI_API_KEY`,
используется он, а сохранённый в дэшборде ключ игнорируется, и карточка честно
пишет «из окружения». Это гарантия, что правка в админке не может молча
изменить поведение прода.

## Что нужно один раз настроить

В переменных окружения Vercel (Production и Preview):

```
INTEGRATIONS_SECRET=<случайная строка от 32 символов>
```

Сгенерировать: `node -e "console.log(crypto.randomUUID()+crypto.randomUUID())"`.

**Менять эту переменную — значит потерять все сохранённые ключи**: расшифровать
старые записи новым мастер-ключом нельзя. Дэшборд в этом случае покажет
провайдеров как ненастроенные, ключи нужно будет ввести заново. Ронять сайт это
не может — расшифровка никогда не бросает исключение.

## Как добавить новый API

Владелец говорит в чате: «подключи такой-то сервис». Дальше:

1. **Добавить запись в `INTEGRATIONS`** (`src/lib/integrations/registry.ts`).
2. **Добавить пробу в `probes.ts`** — самый дешёвый запрос, который проверяет
   именно ключ. Для OpenAI-совместимых API уже есть `probeOpenAiCompatible`.
3. Всё. Карточка, форма, маскирование, health и выбор модели появятся сами.

Шаблон записи:

```ts
{
  id: 'deepseek',                    // латиница, стабильно: это ключ строки в Airtable
  name: 'DeepSeek',
  category: 'magicbox',              // 'llm' | 'core' | 'magicbox'
  summary: 'Дешёвые модели для массовых задач.',
  consoleUrl: 'https://platform.deepseek.com/api_keys',
  docsUrl: 'https://api-docs.deepseek.com/',
  probe: probeDeepSeek,
  fields: [
    { key: 'apiKey', label: 'API-ключ', secret: true, required: true, envVar: 'DEEPSEEK_API_KEY' },
    { key: 'model', label: 'Модель по умолчанию', secret: false, required: false, isModelField: true },
  ],
}
```

Правила по полям:

- `secret: true` → значение шифруется, наружу уходит только маска, пустой ввод
  в форме означает «не менять». Так помечается всё, что даёт доступ.
- `secret: false` → открытая настройка (модель, идентификатор базы, список
  адресов). Хранится в поле `Config` открытым текстом и показывается целиком —
  секретов туда класть нельзя.
- `envVar` — имя переменной окружения, которая перекроет сейф. Указывать всегда:
  это путь отхода, если сейф недоступен.
- `isModelField: true` — поле получит выпадающий список живых моделей провайдера.

Правила по пробе:

- обязательный таймаут (в `probes.ts` он уже общий — `request()`);
- любой текст, уходящий наружу, прогонять через `redact(text, [секреты])`, если
  секрет мог попасть в URL;
- ошибку описывать по-русски и по делу: читает её владелец, а не разработчик.

## Как пользоваться ключами из кода

```ts
import { findIntegration } from '@/lib/integrations/registry'
import { isEnabled, resolveCredentials } from '@/lib/integrations/vault'

const definition = findIntegration('openai')
if (definition && (await isEnabled(definition))) {
  const { apiKey, model } = await resolveCredentials(definition)
  // apiKey — расшифрованное значение. В браузер и в логи не отдавать.
}
```

`resolveCredentials` сам разбирается, брать значение из окружения или из сейфа.

## Чего здесь намеренно нет

- **Истории проверок.** Это был бы отдельный поток записи в Airtable ради
  данных, которые устаревают за минуту. Состояние проверяется по кнопке.
- **Расхода и лимитов.** Из провайдеров моделей биллинг по API-ключу отдаёт
  только OpenRouter (и он это показывает). У остальных цифра либо закрыта, либо
  требует отдельного ключа с правами на биллинг — заводить такой ключ ради
  строчки в интерфейсе опаснее, чем полезно.
- **Роута, отдающего сохранённый ключ.** Ни одного. Ключ можно только заменить.
