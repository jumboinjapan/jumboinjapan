# M5 — подбор POI для программы

Статус: реализован, локальная приёмка пройдена. База: `e87482338959a210c82297d381df0f4c90223cab`, отдельный checkout `jumboinjapan-geography-audit`.

## Контракт изменения

Общий компонент подбора используется конструктором многодневной программы и редактором остановок. Канон свойств — реестр M1; оценка — `matchesPoiMatrix`, география — `matchesPoiGeography`. Сервер читает всю базу, применяет обязательные условия, ранжирует по предпочтениям и лишь затем выбирает страницу. Неизвестные условия отделяются от подтверждённых запретов. Источники совпадений доступны гиду.

Пожелания из анкеты v3 и структурированных старых полей преобразуются одним адаптером. Свободный текст не превращается в запреты. Гид явно применяет предложенные условия. Наборы условий сохраняются в браузере без переноса профиля и контактов клиента; между устройствами не синхронизируются.

Выбор вызывает существующий обработчик добавления POI. Новый подбор не создаёт POI, не меняет их матрицу и не перестраивает сохранённые маршруты. Системные точки остаются в прежнем поиске.

## Реализация и границы

- `scripts/poi-portals/lib/poi-matrix-planning.mjs` — серверный отбор `poi-planning-query/v1`, результат `poi-planning-result/v1`, преобразование профиля `poi-planning-profile/v1`.
- `src/components/admin/PoiPlanningPicker.tsx` — общий компонент. Обязательные свойства внутри группы по умолчанию объединены через «или»; можно выбрать «все». Между группами действует «и». Предпочтения ранжируют по числу подтверждённых совпадений.
- `GET /api/admin/multi-day/pois?selection=…` — авторизация и проверка запроса до чтения. Все страницы Airtable прочитаны до фильтрации и пагинации по 20 результатов. Прежний `?query=…` сохраняет прежний формат и поиск системных точек.
- Поле «Возраст детей» учитывает подтверждённый отрицательный вывод только в названном диапазоне. Положительная рекомендация для 6–12 лет не становится запретом для другого возраста. Закрытие, подтверждённое досье принятой матрицы, исключает место; противоречивый статус требует проверки.
- Незаполненная матрица остаётся в общем поиске без требований. При обязательном свойстве она попадает в «Нужно проверить». Известные свойства родителя не наследуются точками посещения.
- Основания показывают текст факта, условия и ссылку. Переход `/admin/seo-llm?poi=POI-…` открывает именно нужную карточку. Запросы и ответы связаны: устаревший ответ не показывается под новыми условиями.
- Профиль строится из `parseStoredProfile` и полей `Children/Mobility/Interests/Pace` старой карточки. Из произвольного текста ограничения не извлекаются. Контакты, имя, заметки клиента не входят в сохраняемый запрос. Свободные пожелания и просьба предложить занятия обозначены напоминанием гиду.
- Конструктор получает POI через прежний `handlePoiSelect`, редактор остановок — через прежний `handleAddStop`. Сохранение программы, порядок, цены и ручные тексты не менялись. В редакторе остановок кнопка блокируется на время существующей операции сохранения.
