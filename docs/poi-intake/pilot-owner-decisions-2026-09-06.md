## III. Решение 07.09.2026 — проверки не должны зависеть от терминала владельца

Контекст: условие слияния «один непрерывный `npm run verify` на Node 22» (II‑2.1) удалось
выполнить только вручную владельцем: оболочка агента обрывает процесс через 180 секунд, а
правило II‑5.1 требовало отдельного разрешения на каждый прогон. Слова владельца: «если
правило скилла мешает запускать проверки, то его нужно поменять. Мы не можем строить
разработку, базируясь на моём физическом доступе к терминалу».

| № | Вопрос | Решение | Следствие |
|---|---|---|---|
| III‑1 | Постоянное правило для read-only стадий `verify`? | **Да, в формулировке:** read-only стадии `npm run verify` (целиком или любую стадию отдельно) агент запускает без отдельного разрешения — только GET, без `--write`/`--apply`, лог в `tmp/`, факт живого чтения и список прочитавших базу стадий названы в отчёте; прочее чтение с ключами и все записи — как прежде | Правило внесено в `.agents/skills/jj-db-dev/SKILL.md`, `AGENTS.md` § 4, карту § 10, `change-policy.md` § 18; II‑5.1 сужено, не отменено |
| III‑2 | Где живёт непрерывный `verify`, не зависящий от терминала владельца? | **CI с read-only токеном Airtable** | Владелец кладёт в секреты GitHub PAT только на чтение записей и схемы базы; `verify.yml` выполняет те же стадии с этими секретами; доказательством условия II‑2.1 становится лог Actions. Локальный раннер (launchd) — не выбран |
