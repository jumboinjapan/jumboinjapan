## Что исправлено по ходу

- 36 муниципалитетов в разборе японского адреса и 35 направлений в каноне: портал иногда относит место к соседнему туристическому городу. Префектура подтверждается адресом места; пример — Ониосидаси в Гумма при направлении статьи Каруидзава.
- Полные японские названия и адреса дали дополнительные совпадения Google. Кацурахама в Коти заменяет отклонённую точку одноимённого пляжа без подтверждённой префектуры. Норикура привязана к префектуре фактической точки вершины.
- Энцуин отделён от соседнего Дзуйгандзи и его музея по официальному плану территории. Совпадение Google Place ID всё равно запрещает дубль.

## Факты и расходы

Прочитаны все содержательные блоки 100 страниц, сведения о проезде и посещении. Просмотрены 380 уникальных медиафайлов портала, включая карты; отдельно просмотрены изображения и схемы для Хара/Ундзэн. Полные HTML, изображения, выгрузки и Google-ответы остаются в локальных рабочих артефактах, в Git не добавлены. В базу записаны самостоятельные факты и тексты.

У каждой новой карточки досье находится в Notes и доступно админке. У 100 исходных страниц было подготовлено 2125 фактов; у четырёх карточек Хара — ещё 88. В 85 созданных карточках сохранено 1815 фактов. Остальные досье не выдаются за записанные в существующие или отложенные POI.

Зафиксировано **195 фактических вызовов Google Text Search**: 138 основного поиска, 33 диагностики, 18 полного имени, шесть дополнительных уточнений (включая два ребёнка Хара). Модельных API-вызовов нет. Фактическая сумма списаний не проверялась; расчётная стоимость не называется расходом.

## Исполнение и восстановление

Рабочие артефакты: `tmp/jg-next100-2026-09-11/`. Успешные создания: `tmp/poi-jg-runs/jg-next100-live-1`, `-live-2`, `-live-4`, `-live-5`, `jg-next100-review-write`, `jg-next100-nagano-write`. Каждая запись прошла штатный Intake, журнал намерения и независимое чтение. Порции записи не превышали 25; общий lock исключал пересечение писателей.

`jg-next100-live-3` остановился при репетиции: английское Golden Week не прошло канон часов. POST = 0; русский текст исправлен, использован новый run ID.

Шесть связей записаны `poi:jg-copy`, журнал `tmp/poi-jg-copy-runs/jg-next100-links/`. Три связи Хара созданы вместе с детьми.

Коррекция собственных Draft/Todo использует общий withVerifiedUpdates. Первая серия из шести строк остановилась после третьего PATCH: Airtable удалил очищенное поле множественного выбора, а карточка ожидала `[]`. Два предыдущих исхода были verified; третий сохранён как mismatch, исходный журнал не переписан. Свежим чтением всех полей подтверждено применение трёх строк. Для очистки в следующей карточке использован `null`; ранее применённые строки исключены. Новая серия записала только оставшиеся три строки, повторного PATCH применённых строк не было.

Доказательства коррекции: `corrections/jg-next100-corrections-write/` и `corrections/jg-next100-corrections-recovery/`. Две первые попытки read-only preflight отказали до PATCH (форма параметров GET и сравнение сырой EN-копии с уже нормализованной); третья проверила все шесть строк. Окончательный отчёт recovery подтверждает все ожидаемые поля шести записей.

Независимая итоговая сверка `verification-complete.json`: база 745, новых 85, прежних без изменения 660, дублей Source Key и POI ID нет, публикация не затронута. Сравниваются намерения создания плюс точные последующие карточки обновления; исходы CLI сами по себе доказательством не считаются.

## Проверка проекта

Полный verify до записи прошёл (`verify-prewrite.log`, exit 0). Следующий полный прогон сохранил exit 1 на пяти нарушениях топонимов (`verify-final.log`); они исправлены. Прогон `verify-complete.log` сохранил exit 1 на четырёх нарушениях в двух последних созданных карточках (Энцуин и музей Нагано); они исправлены отдельной серией из двух PATCH. Итоговая сверка всей базы дополнительно проверяет канон каждого русского поля. Итоговый непрерывный `npm run verify` на Node 22.23.0 завершился с **exit 0**, включая build: `verify-accepted.log` и `verify-accepted.exit`. Пройден весь объявленный набор тестов; сообщения о штатных пропусках сохранены в логе и не выдаются за живые проверки. Стадии canon, polivanov, copy, poi, images и build выполнялись с доступным токеном и разрешёнными чтениями базы по III/VI. Секреты не выводились, этот прогон записей не делал.
