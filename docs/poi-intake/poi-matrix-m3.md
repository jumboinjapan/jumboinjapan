# Матрица POI: запись и адаптеры M3

15.09.2026. Реализованы создание и обновление матрицы существующими писателями.
Сам пакет M3 не выполнял живую миграцию. Поле создано и первые 50 матриц
записаны следующим [пилотом M4](poi-matrix-m4.md). Пустое поле само по себе не означает
классификацию базы. M1 прошёл отдельную независимую приёмку на `7ae185a`.

## Один путь для всех порталов

`ingestPoi` принимает необязательный `poi.matrix`; Japan Guide передаёт `matrix`
из строки `--facts`, Visit Hokkaido — из строки `--portal-batch`. Новый адаптер
передаёт тот же объект в общий Intake. Самостоятельной записи, второго POST или
последующего PATCH матрицы при создании нет.

Для миграции только матрицы M4 тот же `poi:sync` принимает пакет
`poi-matrix-update/v1`: `{spec, rows}`, от 1 до 25 строк. Строка содержит
`recordId`, фактический `sourceKey` записи (или null), `nameRu`, полный
`previousFields` и `matrix` с независимой проверкой. `matrixUpdateProposal`
сверяет свежие поля и предлагает ровно `POI Matrix`; Notes, описания, тип,
координаты, связи и статусы не переписываются. Все строки проверяются до I/O,
затем действует общий исполнитель: lock, схема, свежее чтение, журнал и
проверка результата. Повтор уже применённой строки даёт `noChange`.
Использовать этот режим, когда досье уже пригодно и не требует дополнения.
Если фактов недостаточно, сначала исследовать и дополнить досье существующим
фактическим процессом; отсутствие матрицы не заменять придуманными свойствами.

Для известных мест `poi:sync` принимает `matrix` в строке `poi-fact-sync/v1`.
Матрица проверяется по итоговому досье после `mergePortalFacts` и фактическому
типу записи. Нельзя привязать её к входному досье другого портала вместо
итогового: идентификаторы фактов после объединения могут измениться.

Отсутствующее предложение сохраняет совместимость прежнего импорта. Это
«матрица не заполнена», а не автоматические свойства из старой категории.
Явные `null`, пустое предложение, лишние поля и неизвестные коды отклоняются.
Смысл фактов оценивают автор и отдельный редактор; валидатор проверяет форму,
предмет, ссылки и сроки, но не доказывает смысл произвольного текста.

## Идентичность документа

Reader сохраняет поддержку `poi-matrix/v1`. Запись использует `poi-matrix/v2`;
реестр свойств остаётся прежним — новый список категорий не создавался.

У новой записи `poiId: null`: номер выдаёт хранилище, и при конфликте номеров
оно может его изменить. Матрица привязана к непустому `Source Key`, имени,
типу и отпечатку досье. Reader требует этот ключ в самой записи и подставляет
её фактический POI ID в проекцию. Угадывать следующий номер или дописывать его
в матрицу отдельным PATCH нельзя.

При обновлении документ содержит настоящий POI ID из проверенной записи.
Старое досье общего sync может иметь ключ `poi:POI-xxxxxx`, даже если позднее
в записи появился ключ портала. Такой ключ принимается только при точном
совпадении номера досье с POI ID этой записи; чужой номер не допускается.
Старая матрица сначала проверяется по прежнему досье; новая — по итоговому.
Вход клиента не заменяет свежего чтения: существующий исполнитель сравнивает
все `previousFields`, затем перечитывает запись перед каждым PATCH.

## Предложение и редакторская проверка

Форма `matrix`: `{claims, assessedAt, review}`. Свойства имеют прежнюю форму M1.
`buildMatrixWrite({claims, assessedAt}, context, previousContext)` строит полный
документ для проверки; `matrixContext(fields, now)` получает контекст из полей
и Notes. Для создания POI ID равен null, для обновления — реальному номеру.

`review` имеет spec `poi-matrix-review/v1`, `matrixDigest`, `policyDigest`,
разных `author` и `reviewer`, `checkedAt`, `checks`, пустой список `issues`.
Набор проверок и параметры — `MATRIX_WRITE_POLICY` из
`scripts/poi-portals/lib/poi-matrix-write.mjs`; отпечаток —
`matrixWritePolicyDigest()`. Редактор подтверждает весь итоговый документ,
включая сохранённые свойства, а не только добавленные строки. Его оценку
нельзя подменять собственным исполнением под другим именем. Код проверяет
различие имён, но реальную независимость обеспечивает рабочий процесс.

Изменяемые утверждения допускают не более 30 дней от `checkedAt` до
`validUntil`; конкретное условие может требовать более короткого срока.
При записи срок должен ещё действовать. Исторические свойства не имеют
срока истечения. Редакторская проверка актуальна 30 дней и не может
предшествовать оценке. Ограничение объёма документа — 90 000 байт UTF-8.

## Дополнение без потерь

Неперечисленные свойства остаются в документе и заново проверяются по фактам.
Переданное свойство заменяет прежнее с тем же кодом; отсутствие свойства не
удаляет и не опровергает его. Противоречие требует явного состояния и оснований.
История исправленных фактов сохраняется существующим fact-sync.

Если меняется досье или тип, а старая матрица больше им не соответствует,
запись останавливается до PATCH. Нужно перепроверить матрицу, а не скрывать
ошибку или убирать свойство. Это проверяется и в остальных режимах общего
`poi:jg-copy`: правка описаний/досье не должна незаметно ломать матрицу.
Смена основной категории не входит в предложение матрицы.

## Исполнение и восстановление

Для известного POI используются существующие команды:

```sh
npm run poi:sync -- --packet /absolute/path/packet.json --run-id matrix-preview
npm run poi:sync -- --packet /absolute/path/packet.json --run-id matrix-write --write
```

Сначала dry-run: полная проверка пакета, свежие чтения и сверка поля
`POI Matrix` как `multilineText`. Это не офлайн-команда. Поля и таблица берутся
из прежних источников. Отсутствующая или неверная схема останавливает запись;
автоматического создания поля внутри импортёра нет.

`changes.json` и `report.changes[].matrixChange` содержат старый и предложенный
документы. Карточка, разрешение, before-снимок и журнал — в существующем
`tmp/poi-jg-copy-runs/<runId>/`. Проверка результата перечитывает всю запись,
включая поля вне предложения. Матрица не меняет опубликованные описания,
статусы, координаты или географические связи.

Серия не атомарна. При ошибке или дрейфе после первого обновления сохраняется
подтверждённый префикс, остаток останавливается; отката нет. Неизвестный исход
сначала сверяется по журналу. Повтор неизменного актуального пакета даёт
`noChange`; истёкшая проверка требует новой оценки, а не повторного запроса
с прежними полномочиями. При создании уже существующий Source Key пропускается
при условии, что входной пакет по-прежнему проходит проверки.

## Проверка и следующий этап

`tests/poi-matrix-write.mjs` проверяет создание/чтение/фильтр, обязательную схему,
сохранение свойств, старый формат, подмену фактов, редакторскую оценку, сроки,
строгие runtime-входы, частичное выполнение, неопределённый исход и повтор.
Тесты CLI Japan Guide и Visit Hokkaido подтверждают передачу матрицы через
настоящие пути подготовки. В тестах используются синтетические оценки;
они не служат классификацией реальных POI.

M4: свежая схема и снимок, создание поля при его отсутствии, 50 карточек
с фактическими основаниями и отдельной редакторской проверкой. Затем запись
порциями штатного sync и проверка человеческих фильтров на живых данных.
Фудзи и её географические связи этой миграцией не переопределяются.
