# Общий процесс сбора и дополнения POI

Поручение владельца 13.09.2026, решение XX. Аудит и изменения:
`system-audit-2026-09-13.md`. Japan Guide завершён в своей основной очереди;
эта работа не запускает заново завершённые партии и не регистрирует отложенные
центры городов. Новые адаптеры используют общий процесс ниже.

## Ответственность слоёв

Адаптер знает устройство источника: ключи, страницы, содержательные разделы,
таблицы, карты, подписи и дочерние объекты. Он не создаёт свой writer, matcher,
таксономию, резолвер или правила публикации. Источники разных порталов могут
описывать одну запись базы. Её recordId и основной Source Key сохраняются;
новое происхождение видно в источниках досье, а не в перезаписи основного ключа.
Для старой записи без Source Key передать `sourceKey: null`: досье получает
ключ `poi:POI-…` из существующего POI ID. Само поле Source Key не заполняется.

Фактолог читает полный пакет, проверяет предмет и спорные утверждения. Копирайтер
пишет самостоятельный текст; другой редактор проверяет его. Код проверяет
форму, полноту ссылок, состав партии, прежние поля, допустимые изменения и
результат записи. Код не умеет удостоверять смысл статьи или личность редактора.

## Последовательность для нового адаптера

1. Зафиксировать origin, разрешённый путь доступа, robots, ограничения хранения
   и бюджет. Использовать `source-policy.mjs`, `network-boundary.mjs` и
   `official-page.mjs`. Редирект — отдельный запрос с новой проверкой и бюджетом;
   HTML вместо robots не даёт разрешения. Ошибка нашего кода не становится
   исходом «источник ничего не сообщил».
2. Отбирать содержательную область явно. Общий `parsePortalEvidence` сохраняет
   текст, даты, заголовки, ссылки и media; не наследует исключение article header,
   footer и навигационных блоков от Japan Guide. Селектор и исключения записаны.
   Обработка только выбранного контейнера не называется чтением всего сайта.
3. Сохранить исходные байты и доказательство в `tmp/`, затем заполнить досье
   `poi-facts/v2`. Все блоки получают исход: факт, обоснованно нерелевантно или
   не разобрано. Карты/PDF/изображения смотрит агент; ссылка сама по себе не
   подтверждает просмотр. Пустые `copy.ru/en` допустимы на этой стадии.
4. Передать всю географию и варианты имён общему резолверу. `notFound` допустим
   только после состоявшегося поиска: фиксировать запрос и фактический исход.
   Различать «не искали», «поиск отказал», «несколько точек», «не найдено».
   Центр карты — поисковая подсказка, не точка объекта. Родитель, объект и ребёнок
   опознаются раздельно. Сохранённые пригодные ответы переиспользуются.
5. Общий matcher определяет новые, существующие и спорные записи. `existing` и
   `already_ingested` означают отсутствие нового POST, но не конец обогащения.
   У существующего POI прочитать полную запись и досье, затем подготовить sync.
   Равное имя, домен комплекса или близкие координаты не доказывают тождество.
6. Новое место — прежний `ingestPoi` и проверенный адаптерный исполнитель с
   журналом создания. Для `factDossier.spec = poi-facts/v2` обязательны
   `factEvidence`, `factCopyReview`, `factSubjectAssessment`, совпадение описаний
   запроса с принятыми абзацами. Core проверяет их до чтения схемы/записи.
   Старые входы без досье и v1 сохранены для совместимости; новый адаптер не
   считается подключённым, если обходит v2 через такой вход.
7. Известное место — `poi:sync`, затем независимое чтение всех полей и проверка
   целостности. Карточка обсуждения закрывается по подтверждённому результату,
   а не по факту ответа владельца или HTTP 200. При сбое не повторять всю партию.

## Подготовка доказательства и текста

Общий reader работает на уже полученных байтах, сам в сеть не ходит:

```bash
npm run poi:evidence -- tmp/source-manifest.json tmp/evidence.json
```

Манифест: `file`, `url`, `observedAt`, `sourceKey`, `rootSelector`, `role`.
Роль источника — установленная фактологом принадлежность: official,
publicAuthority, portal или google. URL с правдоподобным названием не делает
страницу официальной. Исходный digest вычисляется из файла. Подключение
другого портала всё равно требует его селектора, политики доступа и тестов;
этот reader не обещает универсальное автоматическое понимание HTML.
Evidence с ролью google нельзя сохранять в постоянное досье: для сведений
Google используется существующий путь опознания с правилами хранения
идентификатора и срока координат. Вложенная карта на странице портала остаётся
подсказкой для поиска; её центр не становится фактом о точке объекта.

Для новой карточки:

```bash
npm run poi:copy-brief -- brief tmp/dossier.json tmp/copy-job.json
```

Для известной карточки сначала подготовить строку sync с `copy: null` и
решениями о фактах, затем:

```bash
npm run poi:copy-brief -- merge tmp/sync-row.json tmp/copy-job.json
```

В задании — все действующие факты, ограничения, реестр политики, канон и стратегия.
Копирайтер возвращает абзацы, редактор — `poi-copy-review/v1` для точного итогового
досье. Сам CLI не вызывает модель и не ставит редакторские подписи.
Роль для агентов: `poi-copywriter.md`; постоянный навык Codex —
`jumbo-poi-copywriter`, роль Claude — `.claude/agents/poi-copywriter.md`.

## Дополнение и разрешение противоречий

Каждый входящий факт имеет ровно одно действие:

- `add`: добавить отсутствующий факт; точный повтор объединяет ссылки;
- `corroborate`: подтвердить прежний текст дополнительным источником;
- `replace`: исправить факт того же предмета и категории, сохранив прежний
  факт, ссылки, проверявшего, дату и причину в `history`;
- `conflict`: сохранить обе версии как противоречивые, не выдавать их за
  основание текста и не переписывать операционное поле.

Неперечисленные старые факты остаются. Исчезновение факта со страницы не означает
ложность или закрытие места. У каждого исправления проверка по свежим official
или publicAuthority, ссылки из самого исправляемого утверждения, действующий
период и причина. Время получения страницы не равно дате вступления изменения
в силу. Агент проверяет это по содержимому, включая сезон и часть комплекса.

Приоритет практических сведений: действующее сообщение оператора → компетентный
публичный орган → остальные источники. Google используется для обнаружения и
перепроверки, но автоматически не перезаписывает режим официального сайта.
Если официального ответа нет, факт сохраняется с состоянием проверки; запись
часов через sync пока требует официального подтверждения. Неизвестность не
подменяется 24/7: `alwaysOpen` требует прямого основания.
Новое предупреждение требует пересмотра оценки посещения. Противоречивый факт
в её основании переводит часы в unknown и статус в conflicting; старое
предупреждение после подтверждённого исправления сохраняется в истории.

Неразрешённые противоречия видны в `report.changes[].unresolved`. Нормальный
следующий шаг — самостоятельная дополнительная проверка агентом. Вопрос
владельцу нужен только для предпочтения, которое источники решить не могут;
в нём должны быть понятные варианты и конкретное последствие выбора.

## Формат sync и запуск

`poi-fact-sync/v1`: `portal`, `rows` (1–25). Строка содержит `recordId`,
основной `sourceKey`, `nameRu`, полные `previousFields`, `incoming`, `evidence`,
проверку `identity`, `changes`, выбор `assessments`, `copy`, `copyReview`,
`writeDrafts`, `fieldUpdates`. Исполняемый пример — `tests/poi-fact-sync.mjs`.
`identity` фиксирует проверку того, что источник относится ко всему нужному
объекту. `mergePortalFacts` возвращает готовые ID фактов для копирайтера.

```bash
npm run poi:sync -- --packet tmp/sync.json --run-id portal-sync-check
npm run poi:sync -- --packet tmp/sync.json --run-id portal-sync-write --write
```

Обе команды используют существующий `copy-japan-guide.mjs` → `withVerifiedUpdates`
→ `airtable-store.update`. Историческое имя файла не ограничивает новый формат.
Новый POST/PATCH-клиент не создан. Предпроверка читает базу; отсутствие `--write`
означает ноль PATCH. Результаты — `tmp/poi-jg-copy-runs/RUN/`, общий локальный
lock с Intake — `tmp/poi-jg-runs/`. Это блокировка одного checkout, не
распределённая блокировка между серверами. До переноса cron на другой хост
нужен общий исполнитель/lock; два независимых писателя запускать нельзя.

Разрешены Notes, оба Description Draft только для Draft/Todo, Working Hours
и Website по проверенному факту. Публичные тексты и статусы не меняются;
для опубликованного места досье обновляется, отчёт отмечает сохранение публичного
текста. Смена точки остаётся в существующем координатном процессе: sync не
принимает Latitude, Longitude, Place ID или политику точки. Закрытие хранится
в оценке посещения досье; это не автоматическое снятие карточки с публикации.

Вся партия проверяется до первого PATCH, а каждое полное прежнее состояние —
ещё раз непосредственно перед ним. Успех подтверждается независимым чтением.
Повтор точного результата — `noChange`; дрейф, потерянный ответ и частичная
запись останавливают остаток. Отката нет. Разбор — прежний `poi:reconcile`;
исходный журнал не изменять. Сохраняются `before.json`, `card.json`, `changes.json`,
`journal.ndjson`, `after-*.json`, `report.json`. `changes.json` — предложение;
применение подтверждают терминальные состояния в report/journal.

## Приёмка адаптера и выпуск

Обязательны положительные и отрицательные сценарии: полный текст/карта/alert;
структурный отказ вместо пустоты; родитель/ребёнок/одноимённые места; передача
адреса и японского имени в поиск; отсутствие поиска не равно notFound; сохранение
старых фактов; официальное исправление с историей; неразрешённый конфликт;
неизвестные часы; неприемлемый текст; повтор; частичный сбой и чужая правка.
Проверять настоящий Intake/store, а не только подготовленный JSON.

Перед live-изменением схемы подготовить и закоммитить совместимый код, проверить,
что старые CI-прогоны не читают базу, выполнить ограниченную согласованную смену
схемы и отправить код. Не менять схему параллельно со старым verify: именно это
вызвало ошибку public_space 12.09.2026. Сам аудит не требует новой схемы.
Полный `npm run verify` с сохранением exit-кода, проверка CI и перечитывание
живого результата обязательны по уровню изменения.
