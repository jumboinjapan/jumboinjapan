# Рабочая очередь Japan Guide

Адрес: `/admin/poi-review`. Вход — существующая сессия админки. Ссылка «Разбор импорта» находится на экране POI.

Владелец комментирует отдельные места и меняет статус разбора. Агент читает те же обсуждения, отвечает, исправляет код и обновляет карточки очереди. Экран не запускает парсер, не создаёт POI и не публикует описания. Статус «Можно продолжать» относится к очереди; проверки приёма обязательны.

Начальная партия — 50 строк от 09.09.2026: `src/data/poi-review-seed.json`. Это краткая проекция рабочего отчёта, без текстов Japan Guide и сырых ответов Google. `sourceKey` связывает её с парсером. При перезапуске/деплое исходная партия объединяется с сохранёнными изменениями.

Обсуждения хранятся в отдельной таблице, имя которой объявлено в `src/lib/airtable-schema.ts`. Схема — `REVIEW_TABLE_DEFINITION` в `poi-review-storage.ts`. Каждое действие дописывает строку; обновление партии не переписывает историю или текущий статус существующей карточки. Клиент повторяет неподтверждённую отправку с прежним UUID, хранилище сначала ищет этот UUID. Одинаковые повторные события сворачиваются при чтении, конфликт содержимого останавливает загрузку. Успех отправки показывается после чтения созданной строки по recordId.

Сервер использует имеющиеся AIRTABLE_TOKEN / AIRTABLE_BASE_ID. Новая таблица не имеет связей с POI и не читается публичными страницами. Транспорт допускает только GET и POST к таблице обсуждения; операций удаления нет. Нет новых паролей, внешних сервисов или публичных API. Автор комментария из браузера назначается сервером после проверки сессии; агент пишет через CLI с пометкой agent.

Внешние пробелы и переводы строки в реквизитах удаляются до сборки адреса и заголовка запроса. Пустое после очистки значение останавливает обращение к базе. Регрессия от 09.09.2026: перевод строки в AIRTABLE_BASE_ID на Vercel превращался в часть адреса и давал 404; локальные реквизиты его не содержали. Проверка открытия страницы без входа не доказывает загрузку очереди: после деплоя нужен успешный GET `/api/admin/poi-review` из авторизованной сессии с проверкой списка.

## Рутина агента

Перед обработкой очередной партии прочитать комментарии:

```bash
npm run poi:review -- list --needs-reply
```

Ответить и обновить состояние:

```bash
npm run poi:review -- comment japan-guide:e3879 --file tmp/response.txt
npm run poi:review -- status japan-guide:e3879 in_progress
```

Пополнить очередь или уточнить причины — массив полных ReviewItem по контракту `src/lib/poi-review.ts`; пример структуры — начальная партия:

```bash
npm run poi:review -- import --file tmp/review-items.json
```

Импорт сначала проверяет все строки. Затем дописывает отдельные события только для изменившихся карточек; на частичном отказе предшествующие события остаются. Локальные намерения и подтверждения CLI — `tmp/poi-review-operations/`. Повтор записи с неизвестным исходом: прежний `--event-id` из журнала. Нельзя выдавать прочитанный комментарий за исполненную задачу: ответ должен назвать результат, а не только убрать отметку ожидания агента.

Новые комментарии сами не запускают вычисления. Агент читает их при начале/продолжении работы. Экран обновляет обсуждения при возвращении на вкладку, раз в минуту на открытой вкладке и по кнопке «Обновить». Неотправленный текст сохраняется только на текущем устройстве; отправленные комментарии доступны со всех устройств.

## Рабочий список и архив

По умолчанию открывается «В работе». `done` и `deferred` без нового обращения
владельца находятся в «Архиве»; «Все» сохраняет доступ ко всей истории. Счётчики
и список используют одно правило. Завершённая карточка уходит и из списка,
и из открытой рабочей области: выбирается следующая доступная карточка.
Ссылка на карточку сама по себе не включает «Все». Явно выбранная вкладка
сохраняется в параметре `view`; ссылка на архивную карточку из рабочей вкладки
предлагает открыть архив.

Новый комментарий владельца к завершённой или отложенной карточке возвращает её
в рабочий список и «Ждут агента» до ответа агента. Явный выбор владельцем
«Завершено» или «Отложено» закрывает ожидание ответа. На карточке «Нужен выбор»
с полученным комментарием показывается «Ответ получен»: это задача агента,
а не доказательство выполненного импорта.

Подпись и фильтр используют одно вычисленное состояние: «Ответ получен» не
попадает в «Нужен выбор», а «Новое обращение» — в «Завершено» или «Отложено».
Исходный статус в журнале при этом сохраняется. Варианты фильтра показывают
число карточек в текущей вкладке с учётом поиска; нулевые варианты недоступны.
Если выбранный фильтр опустел после обновления, экран сообщает об этом и
предлагает сбросить фильтры. Отдельное действие «Изменить статус» дописывает
обычное событие, а не записывает вычисленные состояния в базу.

После проверенного результата агент обновляет причину и следующий шаг через
`import`, затем явно ставит `status <sourceKey> done`. Одного `initialStatus`
в импортируемой карточке недостаточно: импорт сохраняет текущий статус и
комментарии. До закрытия нужно заново прочитать обсуждение; новое неисполненное
поручение не закрывают вместе с результатом предыдущей работы. Решение «пока
не использовать» оформляется как `deferred`. Сам факт наличия POI в базе
не закрывает дополнительные задания по нему.

## Первичная настройка

```bash
npm run poi:review -- schema
npm run poi:review -- schema --apply
```

Создаётся только отсутствующая таблица обсуждения. При несовместимой существующей схеме команда останавливается, не исправляя поля. После создания повторно читает схему. Строки начальной партии не требуют отдельной загрузки в Airtable.

Проверки: `node tests/poi-review.mjs`; полный `npm run verify`. Браузерные проверки записи выполняются с подменённым хранилищем; живые проверки авторизации не отправляют комментариев от имени владельца.
