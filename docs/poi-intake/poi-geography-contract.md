# Географический охват и связи мест — контракт `poi-geography/v1`

15.09.2026. **Статус: внедрено для Фудзи.** Поле создано; родитель POI-001251
и восемь связей записаны и проверены. [Живой результат](fuji-geography-results-2026-09-15.md).
Другие крупные родители этим запуском не изменялись.

Поручение владельца: крупный POI (гора, архипелаг, массив) должен находиться по
любой подтверждённой территории охвата, а карточка — различать принадлежность,
тематическую связь и соседство. Полная матрица категорий
(`poi-matrix-rollout.md`) в этот контракт не входит; охват и связи — её слой
«География и связи», реализованный отдельным контрактом.

## Что уже есть и что переиспользуется

| Понятие | Существующее хранение | Reader / writer |
|---|---|---|
| Префектура ТОЧКИ | `Prefecture (EN)` / `Prefecture (RU)` | `readPoiGeography` (`src/lib/poi-geography.ts`); Intake через `resolved.prefectureEn` |
| Направление маршрута | `Site City` | фильтр «Направление»; не доказательство принадлежности |
| Входит в состав | `Parent POI` (linked) | `ingestPoi` (`Parent POI` при создании), `poi:jg-copy` с пакетом связей для существующих; цикл и висячие ссылки — `check-poi-integrity.mjs` |
| Доказательства | досье `poi-facts/v2` в Notes; реестр `config/poi-japan-guide-review.v1.json` | `readPoiFacts`; `japan-guide-review.mjs` |

Новых writer нет. Охват и связи пишут те же два пути, что и `Parent POI`:
создание — `ingestPoi`, существующие записи — `poi:jg-copy` с пакетом связей.

## Хранение: одно поле, один документ

Поле POI **`POI Geography`** (`multilineText`), значение — документ
`poi-geography/v1`. Это единственное место правки. Список префектур через
запятую в `Prefecture (EN)` не записывается; `Site City` и `Parent POI`
не переопределяются.

```json
{
  "spec": "poi-geography/v1",
  "updatedAt": "2026-09-14",
  "territories": [
    { "prefectureEn": "Yamanashi", "municipalityJa": null,
      "status": "verified",
      "source": { "url": "https://…", "checkedOn": "2026-09-14", "factId": null, "decisionRef": "owner/chat/…" } }
  ],
  "relations": [
    { "kind": "viewOf", "target": { "poiId": "POI-000123", "recordId": "rec…" },
      "direction": "outbound", "status": "verified",
      "source": { "url": "https://…", "checkedOn": "2026-09-14", "factId": "f7", "decisionRef": null } }
  ]
}
```

Правила документа (исполняются `assertPoiGeographyDocument`, `src/lib/poi-geography-document.ts`):

* точные ключи на каждом уровне; только собственные JSON-данные без геттеров, скрытых свойств и пропусков в массивах; проверка возвращает отдельный снимок значений; `updatedAt` — календарная дата;
* `prefectureEn` — каноническое английское имя из `prefectures.ts`;
  `municipalityJa` — либо `null`, либо муниципалитет в том виде, в каком его
  разбирает `parseJapaneseAddress` вместе с префектурой (`山梨県富士吉田市` →
  `富士吉田市`); пара «префектура + муниципалитет» — тождество территории,
  голое имя муниципалитета без префектуры не принимается;
* `status` ∈ {`verified`, `reported`}; фильтры учитывают только `verified`;
* `source.url` — https; `checkedOn` — календарная дата; `factId` и `decisionRef`
  — строка или `null`, хотя бы одно из них названо;
* `kind` ∈ {`viewOf`, `dedicatedTo`, `visitPointOf`}; `direction` всегда
  `outbound`: документ описывает отношение ЭТОЙ записи к цели, обратная сторона
  выводится читателем и никогда не хранится — так у связи одна правда;
* ссылка на себя — отказ; повтор пары `(kind, target.poiId)` — отказ; повтор
  территории — отказ; ≤ 47 территорий, ≤ 50 связей.

Отсутствие поля или пустое поле — «охват не описан», не отрицательный признак:
старая карточка читается по префектуре точки. Повреждённый документ читается
как ошибка с текстом; префектура точки при этом остаётся видна, ошибка не
скрывается.

## Отношения

| Отношение | Где хранится | Смысл | Направление |
|---|---|---|---|
| входит в состав | `Parent POI` | существующая иерархия; один родитель | ребёнок → родитель |
| вид на объект | `relations[kind=viewOf]` | отсюда виден объект | смотровая → объект |
| посвящён объекту | `relations[kind=dedicatedTo]` | музей, святилище, центр наследия | место → объект |
| точка посещения объекта | `relations[kind=visitPointOf]` | откуда объект посещают | точка → объект |

Принадлежность и роль точки посещения сочетаются: станция на склоне имеет
`Parent POI` = гора и `visitPointOf` = гора. Географическое соседство и
попадание в одну выборку по префектуре связи не создают. Существующая
вложенность не перепривязывается автоматически.

Читатель графа (`src/lib/poi-relations.ts`) по всему списку выводит: детей,
входящие связи (виды на объект, посвящённые ему места, точки посещения) и
состояние каждой связи: `ok`, `dangling` (цели нет), `drift` (`poiId` и
`recordId` цели разошлись), `self`. Циклы принадлежности проверяет
`check-poi-integrity.mjs` (`parent_cycle`); документ их не вводит, потому что
принадлежность в нём не хранится.

## Фильтры

Региональный и префектурный фильтры находят POI, если префектура точки ИЛИ
любая подтверждённая территория охвата попадает в выбор. Один POI входит в
результат один раз. Счётчик у префектуры считает записи, у которых она есть
хотя бы в одной роли, поэтому сумма по префектурам может превышать число POI —
это сказано в интерфейсе. Записи без охвата ведут себя как раньше.

## Конструктор программы

Сценарий выбора остановок не меняется. Опция POI несёт `visitPoints` — входящие
`visitPointOf` со статусом `verified`. Связи `reported` видны с пометкой о проверке, но не предлагаются для программы. Родительская карточка подставляется как есть: вершина или
условная точка автоматически не заменяют вход. Если у выбранной карточки есть
точки посещения, конструктор предлагает их отдельным списком; выбор делает гид.

## Импорт

Страница-каталог портала может описывать самостоятельную локацию. Отчёт JG-1
получает раздел `locations`: страницы-коллекции, возглавляющие ранжирование
(`destinationRanking`), с их ключами, адресом, списком ранжированных страниц и
состоянием в базе. Раздел не входит в закон сохранения очередей и POI не создаёт:
ранжирование не доказывает принадлежность, решение принимает агент по правилу
XVII через существующий реестр `poi-japan-guide-review.v1.json`. Центры городов
остаются отложенными (XVIII).

Реестр review получает необязательные `geographicScope` и `relations`
(источник и факт у каждой строки). Каждая территория и связь содержит
`sourceUrl` и `factIndex` — индекс конкретного факта в `facts`, начиная с нуля.
Для территории обязателен `sourceRole: "official"`: это результат проверки
источника агентом, а не вывод из доменного имени. Код сверяет форму, URL и индекс;
он не доказывает официальность сайта и смысл факта. Источник нужно действительно
прочитать и убедиться, что факт относится к указанной территории или виду связи.
Japan Guide, включая домен без `www`, административным первоисточником не считается.
Одинаковый URL у нескольких фактов не даёт права выбрать первый попавшийся. `prepareReviewedIntake` собирает из них
документ для создания; `reviewLinkProposal` — для существующей записи вместе
с `Parent POI`. Цель связи проверяется по ключу решения, POI ID и record ID; совпадения имени
недостаточно. Для существующего документа предложения добавляют или обновляют
названные территории и связи. Неупомянутые записи сохраняются; неявного удаления
нет. Повтор без содержательных изменений сохраняет прежнюю дату и не предлагает
PATCH. Повреждённый прежний документ останавливает запись.
Карточка позволяет открыть связанное место вне текущего фильтра и вернуться к
выборке, сохранив фильтры.

## Миграция

Схема: одно поле `POI Geography` — карточка в `tmp/poi-geography-migration/…`
по существующему образцу схемной операции; до аудита не исполняется. Данные:
отчёт предложений `old → new` по каждому POI c исходом из закрытого списка
(`create`, `alreadyMatches`, `needsOwner`, `insufficientEvidence`,
`technicalRefusal`), повтор без дублей (сверка с уже записанным документом),
проверка частичного выполнения свежим чтением. Если цель ещё не создана,
строка имеет `technicalRefusal` с `dependsOn` и не содержит нагрузки `new`.
После создания цели нужен новый снимок и пересборка отчёта: частичный документ
не может считаться выполненной связью. Команда —
`node scripts/poi-geography/prepare-geography-migration.mjs` (только чтение файлов).

## Что работает, что план

Работает в коде: документ и его проверка, чтение охвата и связей в списке и
карточке админки, фильтры по охвату, точки посещения в конструкторе, поле в
`ingestPoi` и в `poi:jg-copy` с пакетом связей, раздел `locations` в JG-1, проверка
целостности, подготовка отчёта миграции.

Для Фудзи поле, родитель и связи уже применены. Адзума и остальные примеры
не мигрировались. Повторный запуск сначала сравнивает свежие данные;
совпавшие документы и существующий Source Key не записываются заново.

## Аудит и интеграция 14.09.2026

Пакет проверяется вместе с матрицей M1/M2. Исправлены потеря прежних связей при
дополнении, подмена цели, обход проверки при сериализации, неполные миграционные
нагрузки, включение неподтверждённых точек в подбор и переходы за пределы фильтра.
Тест `tests/poi-geography.mjs` использует только отслеживаемые фикстуры и сам
создаёт временные входы CLI. `tests/fixtures/poi-geography-proposals.json` —
пример для тестов, не проверенное фактическое досье и не разрешение записи.
Поле в живой базе и родитель Фудзи этим аудитом не создаются.

Отсутствие родителя в базе — задача подготовки Intake для агента, а не
автоматический вопрос владельцу. Миграционный отчёт не создаёт POI и возвращает
`technicalRefusal`; если источники не проверены — `insufficientEvidence`.
Владелец выбирает только там, где осталась настоящая неоднозначность.

## Исполнение после аудита

Связи существующих записей: `npm run poi:jg-copy -- --packet FILE`
для просмотра и та же команда с `--write --run-id ID` для записи.
Формат файла — `poi-japan-guide-review-links/v1`. Отдельного флага `--links` нет.
Создание: `poi:jg-intake --review-selection` с досье и доказательствами.
Для досье v2 путь `--facts` передаёт в Intake также `evidence`, `copyReview`
и `subjectAssessment`; отсутствие приёмки не допускает запись.
Подробные журналы и ограничения — в отчёте завершения Фудзи.
