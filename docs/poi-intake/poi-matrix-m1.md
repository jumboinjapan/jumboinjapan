# Матрица POI — контракт M1

14.09.2026. Реализован исполняемый контракт и подготовлены 40 примеров из базы.
Пакет предназначен для независимой приёмки M1. Интерфейс и запись матрицы ещё
не подключены; существующий импорт работает по прежнему контракту.

## Источники правды

Реестр — `config/poi-matrix.v1.json`, единственный loader —
`src/lib/poi-matrix-registry.ts`. Он содержит коды, RU/EN, группы и требования
к основаниям. `scripts/poi-portals/lib/poi-matrix.mjs` проверяет предложения,
строит компактную проекцию и выполняет общий предикат поиска. Код не имеет
сетевых или записывающих операций.

Слой «Что за место» уточняет старый тип: например, аквариум и зоопарк имеют
разные признаки при общем совместимом типе. Несколько признаков допустимы,
если каждый подтверждён. Они не выводятся автоматически из прежней категории.

География и отношения крупных родителей — отдельная задача Claude Code.
Матрица не создаёт собственного списка территорий или родительских связей.
Редакторские отметки также не входят в агентское предложение M1.

## Что означает предложение

Документ `poi-matrix/v1` связан с POI ID, Source Key досье, текущим русским
именем предмета, отпечатком досье и существующим типом. Старые записи могут
иметь Source Key только в досье; непустое поле записи обязано совпасть с ним.
Будущая граница записи должна получить этот контекст из свежего чтения самой
записи, включая Notes. Контекст, переданный клиентом, источником правды не служит.

`buildPoiMatrix` фиксирует агентское происхождение. Документ содержит оценку,
а не разрешение на запись и не редакторское одобрение. Валидатор доказывает
форму и связь с основаниями, но не способен проверить смысл произвольной фразы.
Проверка того, что факт действительно подтверждает свойство, остаётся задачей
автора и отдельного редактора при M3/M4. Например, присвоить «С детьми» только
по детскому билету нельзя даже при корректных ссылках.

У каждого свойства есть состояние, ссылки на текущие факты, отдельные ссылки
на условия, время оценки и обоснование. Для возрастного свойства задаётся
диапазон, для изменяемого — срок проверки. Неперечисленное свойство неизвестно.
Отсутствие, отрицательное основание и конфликт различаются.

Факт должен относиться к тому же предмету, а не к ребёнку. Сведения о составе
не используются для присвоения функций всему родителю. Так родитель сохраняет
возможность показывать музей внутри через отношения, но не получает функцию
музея только по перечню своих частей. Составной объект может иметь несколько
собственных функций, если основания описывают их как свойства самого объекта.

Для семейной пригодности нужны проверенные основания, возрастной диапазон
и отдельный проверенный факт с условиями. Для положительных утверждений о
доступности с коляской и без ступеней также нужны проверенные факты. Отметка
«С детьми» не подразумевает доступность с коляской. Семантическую достаточность
оснований проверяет редактор; эта проверка не подменяется количеством ссылок.

## Время и поиск

Срок применён к отдельному изменяемому свойству. При его истечении свойство
перестаёт проходить строгий фильтр, но исторические темы остаются доступны.
M1 не устанавливает единый производственный TTL: его выбор по классу условия
и источнику входит в M3. Горизонт 14 дней в примерах нужен только для
воспроизводимого теста и не является правилом актуальности живой базы.

Закрытие или конфликт статуса посещения в досье исключает положительные
функции из строгой выборки; темы объекта сохраняются. Это консервативная
проверка состояния всего POI. Будущие отдельные закрытия экспозиций требуют
собственных предметов/условий, а не переноса ограничения на весь комплекс.

Внутри группы — явное «хотя бы одно» или «все», между группами — «все».
Возрастной фильтр проверяет каждого ребёнка. Неизвестное, опровергнутое,
конфликтное, просроченное или недоступное свойство положительного совпадения
не даёт. Пустой запрос не исключает старые записи.

`matchesPoiMatrix` принимает только проекцию, созданную валидатором в том же
процессе. JSON от клиента не принимается как проверенная проекция. При M2/M5
сервер фильтрует до ограничения выдачи, а клиент получает результат и подписи;
не нужно заново оценивать присланную клиентом матрицу на доверии.
Проекция содержит только оценённые свойства и ссылки на их факты. Подписи
берутся из общего реестра один раз; неоценённые свойства подразумевают
«неизвестно», а не раздувают ответ списком всех возможных тегов для каждого POI.

Чтение различает отсутствие матрицы и повреждение. Старый тип остаётся
доступным через нынешний `readPoiCategory`; он не превращается в набор
доказанных матричных свойств. Ошибка матрицы видна явно и не скрывается за
успешным старым типом. Выбранные фильтры не меняют основной тип записи.

## Предложение схемы для M3

Одно новое поле `POI Matrix`, тип Meta API `multilineText`, значение — JSON
документа. Исполняемое предложение — `matrixSchemaProposal`. M1 не создаёт
поле и не добавляет его в живые списки запрашиваемых полей. Расписания, статья
и текст досье в нём не дублируются. Старые поля таксономии остаются на месте.

При M3 подключить поле к существующим Intake и sync, сверить живую схему,
размер документа, свежий контекст и досье перед записью. Нужны отдельные тесты
частичного выполнения, повтора и независимого чтения; M1 их не доказывает.
Изменение текущего типа нельзя прятать в запись дополнительных свойств.

## Примеры и воспроизведение

`tests/fixtures/poi-matrix-annotations.json` — явная разметка по фактам.
`tests/fixtures/poi-matrix-examples.json` — 38 сокращённых фактических досье
и два сценария старого чтения: Одавара и Кайюкан. Полной миграции эти примеры
не заменяют. Среди них комплекс торговли/истории/архитектуры, гора и отдельный
храм, замки, музеи, сады, транспорт, общественные пространства, океанариум
Камо и парки животных. Камо и сафари-парк различаются при одном старом типе.

Сокращённые досье — производные тестовые артефакты, а не полные живые досье:
объекты выбранных фактов и номера источников сохранены, посторонние факты,
блоки, тексты и история исключены; формат переведён в исследовательский v2.
Отпечатки исходной выгрузки и исходных досье сохранены. Airtable recordId и
сырые Notes в git не помещаются. У каждого факта остаются URL и локаторы.

Для воспроизведения на сохранённой выгрузке:

```sh
npm run poi:matrix-fixtures -- tmp/poi-matrix-m1/base.json tests/fixtures/poi-matrix-annotations.json tmp/poi-matrix-m1/rebuilt.json
npm run test:poi-matrix
```

Производный файл создаётся только по новому пути. Изменённый состав базы не
выдаётся за воспроизведение старого снимка. Положительный семейный сценарий
в тесте синтетический и отделён от 40 существующих POI: подходящие возрастные
условия не приписаны реальному месту без отдельной редакторской проверки.

Код M1 проверяется полным `npm run verify`; результаты текущего запуска и
мутаций находятся в `tmp/poi-matrix-m1/`. Этап M2 начинается после приёмки
контракта, а живая миграция относится к M4.
