## Как работает подбор

В `/admin/seo-llm` раскрыть «Подобрать по свойствам», выбрать галочки и нажать
«Показать места». Группы берутся из единого реестра M1. Внутри группы достаточно
любого выбранного свойства; можно явно выбрать «Все выбранные». Между группами
требуется выполнение всех условий. Для «С детьми» указываются возрасты каждого
ребёнка. Основной тип, география, статус и поиск продолжают уточнять выборку.

Применённые условия видны и снимаются по одному. «Сбросить свойства» сохраняет
остальные фильтры. Скрытие панели не отменяет выбор. Ошибка запроса не показывает
старую выборку как новую: при активных свойствах результаты скрыты до успешного
повтора. Без активных свойств общий каталог остаётся доступен.

На карточке — свойства, состояние и раскрываемые факты с условиями, ссылками
и датами источников. Это оценка агента по фактам, не редакторское одобрение.
Метки списка показывают только поддержанные свойства. Отсутствующая матрица
не мешает видеть старую карточку в общем каталоге; повреждённая явно обозначена.

## Единственный путь проверки

`GET /api/admin/poi-matrix?query=<JSON>` защищён существующим `requireAdminSession`.
Полный запрос проверяется до чтения Airtable. Неправильный запрос — 400; ошибка
чтения — 503, а не успешный пустой список. Ответы приватные, без кэширования.

`scripts/poi-portals/lib/poi-matrix-catalog.mjs` читает матрицу с текущими полями
записи и досье из Notes, затем использует M1 `readPoiMatrix` / `matchesPoiMatrix`.
Фильтрация идёт по всем прочитанным неслужебным записям, без лимита первых 12.
Счётчики valid/missing/invalid охватывают тот же состав. Каждый запрос заново
проверяет сроки свойств. До создания поля `POI Matrix` отсутствующие значения
считаются missing; API не требует наличия поля в схеме для чтения каталога.

В браузер идут ID и компактные свойства, без Notes, досье и полного документа
матрицы. Факты открытой карточки загружаются прежним запросом детали; проекция
детали рассчитывается на том же свежем чтении. Изменение досье делает прежнюю
матрицу непригодной для подбора до повторной оценки.

Браузер не реализует вторую проверку матрицы: он пересекает выданные сервером ID
с существующими фильтрами каталога. Отмена предыдущего запроса защищает от поздних
ответов. Обновление списка и сохранение названия повторяют запрос свойств; после правки
названия также перечитываются основания открытой карточки. Кнопка применения позволяет
изменить несколько галочек без полного чтения базы после каждого нажатия.

## Проверка

`npm run test:poi-matrix-catalog` проверяет реальный серверный consumer на 40
эталонах M1: совпадение ID с основным predicate, порядок, повреждённую строку,
отсутствие матрицы, истечение срока, сохранение счётчиков, ошибки до чтения.
Дополнительно выполняются настоящие reader и GET-handler с подменённым HTTP:
отказ авторизации, 400 до чтения, 503, постраничное чтение и отказ на второй странице.
`tests/poi-category.mjs` продолжает проверять общий Airtable-reader; импорт
нового consumer добавлен в тестовую среду без подмены его логики.

Браузерный прогон — локальный Next с фикстурным Airtable и запретом внешней сети.
Такая проверка доказывает работу интерфейса, но не наличие матрицы в живой базе.
Новых писателей, изменений публикации, географии и связей в M2 нет.
