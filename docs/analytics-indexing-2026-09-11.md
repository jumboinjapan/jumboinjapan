# Учёт обращений и готовность страниц к индексации

Задача владельца: выполнить следующий пакет после аудита GA4/GSC от 11 сентября,
не конфликтуя с парсингом POI. Основа — main `ca69ce0`, отдельная рабочая копия
`jumboinjapan-geo`, ветка `codex/analytics-indexing-fix`.

## Контракт изменений

- Сохранить контракт `/api/contact`, поля CRM, маршруты и авторизацию. Успешный
  ответ формы должен показывать успех и вызывать `generate_lead`; отказ сервера
  сохраняет заполненные поля и вызывает `contact_form_error`.
- Публичную аналитику собирать только на HTTPS-доменах jumboinjapan.com и www.
  Не загружать SDK на локальном/preview-хосте или первом открытии служебного URL.
- Исключать `/admin`, `/api`, `/p` и их потомков, а также `/profile/<token>`.
  Общая анкета `/profile` остаётся частью публичной воронки.
- После посещения служебной страницы исключать вкладку до закрытия. Флаг хранится
  в sessionStorage; если оно недоступно — до перезагрузки текущего документа.
  Это предотвращает попадание возвратов из админки в приобретение клиентов.
- Один источник правил — `src/lib/analytics-policy.ts`; потребители — GA4,
  Vercel Analytics и клиентский дубль Funnel Events. API и схема Airtable не меняются.
- Проверка GA opt-out выполняется при чтении штатного `ga-disable-ID`, включая
  изменение history до React effect. Vercel проверяет событие через beforeSend.
  GA сохраняет автоматические просмотры: второй ручной page_view не добавляется.
- Начальный referrer очищается от URL авторизации и частных ссылок; для внешнего
  сайта остаётся origin. Vercel передаёт публичный путь без query/hash.
- Ошибка GA не должна останавливать независимую отправку Funnel Events.
  Тесты подменяют транспорт; тестовые заявки в рабочую CRM не записываются.

## Что изменено

1. В ContactForm ссылка на form сохраняется до await. React обнуляет
   event.currentTarget по завершении синхронного обработчика; обращение к нему
   после fetch было причиной ложного состояния ошибки при успешном ответе.
2. SDK перенесены из безусловного корневого layout в PublicAnalytics. Общие
   правила применяются и к пользовательским событиям trackEvent.
3. Главная получила прямые видимые ссылки на первый и второй день в Токио,
   Никко, Хаконе, Фудзи и «Япония — первое открытие». Каталоги сохранены.
4. Title каталога Токио уточнён: «Экскурсии по Токио с гидом на русском».
   Canonical, Sitemap, JSON-LD и данные POI не изменены.

## Проверки

- `npm ci` выполнен; `npm run verify` прошёл локально. Airtable-ключей в этой
  рабочей копии нет: живые этапы пропускают чтение, это не проверка живой базы.
- `tests/contact-form.mjs` исполняет настоящий обработчик компонента: успех
  после очистки currentTarget, серверный отказ и необязательный JSON-ответ.
- `tests/public-analytics.mjs` проверяет границы URL, отсутствие вызовов обоих
  транспортов на частных/локальных страницах, положительный публичный контроль,
  отказ GA, SPA, повторную инициализацию, opt-out и сохранение исключения вкладки.
  Оба набора включены в `npm test`.
- В изолированной копии возврат `event.currentTarget.reset()` ломает ожидаемую
  проверку успешной заявки; удаление клиентского гейта ломает проверку отсутствия
  отправок. Это проверка исполняемого поведения, а не наличия строки в файле.
- Публичное чтение страниц сохранено в `tmp/analytics-indexing/public-pages-before.json`:
  основные каталоги и маршруты отвечают 200, имеют собственный canonical,
  разрешают индексацию, присутствуют в Sitemap и связаны видимыми ссылками.
  `/city-tour/day-two` отдельно проверен: 200 и собственный canonical.
- Прямые ссылки на главной проверены в локальном браузере. Сборка и CI служат
  дополнительными воротами перед публикацией.
- В браузере проверена production-сборка через изолированный локальный proxy:
  `/api/contact` отвечает тестовыми 200/500, остальные POST запрещены. При 200
  показано подтверждение, форма очищена; при 500 показана ошибка и поля сохранены.
  Журнал `tmp/analytics-indexing/form-browser.log` содержит только подменённые запросы.

## Границы результата

Изменение кода не очищает прошлую статистику и не гарантирует индексацию Google.
Ключевое событие GA4 и нежелательный referrer accounts.google.com требуют
проверки настроек в кабинете; сам факт наличия события в коде не подтверждает
его регистрацию Google. Запросы индексирования и изменения кабинетов нужно
фиксировать отдельно по фактическому ответу интерфейса.

Реальные заявки через рабочую форму для проверки не отправлять. Сначала
использовать изолированный API; после публикации следить за естественными
обращениями. Код парсера, импорт, POI и модерация не входят в этот пакет.

Документация Google: [отключение сбора](https://developers.google.com/tag-platform/security/guides/privacy),
[автоматические просмотры](https://developers.google.com/analytics/devguides/collection/ga4/views).
