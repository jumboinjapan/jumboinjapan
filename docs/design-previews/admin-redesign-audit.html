Админ-панель JumboInJapan · разбор и предложение

Панель собрана вокруг таблиц. Работа идёт вокруг поездок.

Одиннадцать разделов верхнего меню — это одиннадцать таблиц Airtable, вынесенных наружу один к одному. Ни один из них не совпадает с тем, что вы делаете утром: ответить, собрать, отправить, взять деньги, встретить. Отсюда обе жалобы — «не помню, где что редактируется» и «не понимаю, что делать сегодня». Это не мелкие недоделки, это одна структурная ошибка, у которой есть два симптома.

Разобрано по исходникам: 11 разделов, 20 экранов, ~2 400 строк только в трёх самых больших 6 августа 2026
Диагноз

Три ошибки, из которых растёт всё остальное

Первая: разделы названы по хранилищу, а не по задаче

Меню читается так: Workspace · Clients · Resources Library · Route Stops · Multi-Day Builder · POI · Route Texts · FAQ · Журнал · Документ · API. Восемь названий на английском, три на русском, и ни одно из них не совпадает с заголовком экрана, куда ведёт: пилюля «POI» открывает страницу «Редактура» с подзаголовком «SEO и LLM тексты» по адресу /admin/seo-llm, а интерфейс внутри — целиком на английском. Четыре разных имени у одного экрана. Чтобы попасть куда надо, нужно помнить не смысл, а маршрут.

Вторая: один объект живёт на трёх-четырёх экранах

Это главный источник ощущения хаоса. Вещь, которая в голове одна, в панели разорвана на куски, и ни один кусок не знает про остальные.

Что это в головеГде это лежит сейчас
Маршрут «Камакура» Точки и их порядок — /admin/route-stops. SEO-заголовок, описание и вводный абзац — /admin/route-text. Вопросы к маршруту — там же, во вложенном блоке, JSON-строкой в одном поле. Описания самих точек — /admin/seo-llm. Печатный вид — /admin/print/<slug>. Пять экранов. Из «Остановок» есть ссылка на два из них, на билдер — нет.
Место (POI) Текст — «POI». Данные отеля или ресторана — «Resources Library». Переопределение описания внутри маршрута — «Route Stops». Поиск по местам при сборке тура — конструктор, через третий эндпоинт. Одна сущность называется POI, точка и Stop в зависимости от экрана.
Сделка с клиентом Карточка клиента → конструктор (программа) → конструктор же (цена) → отдельный экран /admin/program-share/… в новой вкладке (ссылка гостю) → мессенджер. Три выхода из CRM на одну сделку, два — в новых вкладках. Цены на карточке клиента нет вообще: вопрос «сколько мы ему выставили» с карточки не решается.
Отель Заводится в «Resources Library», ищется в конструкторе, а кнопка «завести новый отель» в «Ресурсах» существует ровно потому, что из конструктора туда ведёт ссылка с параметрами.

Третья: главный экран — отчёт, а не очередь

/admin открывается двумя воронками с полосками и процентами. Блок «Требует внимания» — единственное место во всей панели, где есть понятие срока, — стоит под ними, и покрывает только три стадии из семи. Тур, согласованный, но не оплаченный за два дня до прилёта, не поднимает тревогу нигде. Приезды показаны на дашборде и больше ни на одном экране. Задач, дедлайнов, напоминаний в модели данных нет вовсе.

Утром нужен список дел. Отчёт нужен раз в месяц. Сейчас они стоят наоборот.

И следствие: стадия сделки врёт

Стадию двигают руками из выпадающего списка — это единственный способ. Ни одно реальное событие её не меняет: анкета пришла — стадия та же; программа сохранена — та же; ссылка гостю включена — та же. Оплаты в системе нет вообще, «Оплачен» ставится вручную. При этом факты в базе есть все. Значит, воронка показывает не состояние дел, а аккуратность ведения выпадашки.

Разнобой

Одиннадцать экранов написаны как одиннадцать разных продуктов

В src/components/admin/ui.tsx лежит общий набор примитивов, и в шапке файла прямо написано, что он «и есть механизм консистентности». Половина экранов им не пользуется.

Шесть механик сохранения
  • Сохранение по уходу из поля с бейджем «Autosave» — POI
  • Явное «Сохранить», но «Утвердить черновик» пишет мгновенно — тексты маршрутов
  • «Сохранить (N)», шлёт только изменённое — общий FAQ
  • «Сохранить», всегда активно, шлёт всё — реквизиты документа
  • Отдельная кнопка внутри каждой карточки — API
  • Отправил и очистил — журнал
Пять словарей состояния
  • Draft / Approved / Synced — POI, по-английски
  • «Черновик / Утверждено», чип «на сайте» — тексты маршрутов
  • «На сайте / Черновик / Скрыт» — общий FAQ
  • Draft / Published + «В очереди / Готово к вычитке» — журнал
  • «Работает / Ошибка / Не настроен / Выключен» — API

Плюс: три разных идиомы списка (выпадашки с поиском · сайдбар без фильтра · чипы без поиска), четыре способа раскрыть деталь, три канала обратной связи (тост на 4 секунды · тост навсегда · строка у кнопки), английские служебные подписи в проде («Service module inside Resources», «Unsaved changes for…», «Mark as ryokan»), сырые значения перечислений прямо в выпадающих списках (service, exhibition, draft) — под русскими заголовками. Экран «Журнал» вообще не использует общую оболочку: у него нет ни шапки, ни переключателя темы, ни выхода.

И ни на одном экране нет предупреждения о несохранённом при уходе со страницы.

Срочное

Десять мест, где панель молча теряет вашу работу

Это не про красоту. Это чинится до любого редизайна, отдельными правками, за день-два. Указано, где смотреть.

  • RouteTextWorkspace Переключение маршрута в сайдбаре стирает несохранённое. потеря Флаг «есть правки» в файле вычисляется и нигде не используется: выбрали другой маршрут — черновик перезаписался из базы без вопроса.
  • AdminOperationsConsole Бейдж обещает «Autosave», а сохранение происходит только при уходе из поля. потеря Закрыли вкладку, не кликнув мимо текстового поля, — абзац потерян.
  • AdminOperationsConsole Простой просмотр POI пишет в базу. данные Выбор точки, у которой ещё нет черновика, молча копирует в черновик исходный текст. Пролистали список — насоздавали записей.
  • AdminOperationsConsole Правка опубликованного текста снимает признак «выложено». данные Статус пересчитывается только в «черновик» или «утверждено», значение «synced» теряется.
  • AdminResourcesWorkspace Создание отеля стирает правки в других записях. потеря Буфер правок общий на весь список; после создания страница перезагружает данные, и всё несохранённое исчезает без предупреждения.
  • FaqWorkspace Вопрос без раздела исчезает навсегда. данные Список рисуется только внутри разделов, но в форме есть пункт «— без раздела —». Выбрали — вопрос пропал с экрана, а счётчик «Все» продолжает его считать.
  • MultiDayBuilder Изменение поля «Дней» с 7 на 3 сносит дни 4–7 на нажатие клавиши. потеря Без подтверждения и без отмены. Спасает только серверный предохранитель, и его отказ показывается сырой английской строкой в шапке.
  • MultiDayBuilder Крестик у блока дня удаляет мгновенно. потеря Ни подтверждения, ни отмены, ни уведомления. Кнопка при этом до наведения полупрозрачная.
  • RouteStopsEditor «Вернуть наследование из POI» стирает написанный текст без вопроса. потеря А парная кнопка «Переопределить» при пустом источнике записывает пробел — точка навсегда отвязывается от наследования, и это невидимо.
  • IntegrationsWorkspace «Стереть ключи» — без подтверждения. данные При том что удаление одного POI требует напечатать его идентификатор вручную. Уровень защиты обратен уровню риска.
Мелочи того же рода
  • Перестановка точек в маршруте применяется на экране сразу, а при ошибке сети не откатывается — экран расходится с базой до перезагрузки.
  • Всплывающие меню закрываются только уводом мыши: на тач-экране не закрываются никогда, с клавиатуры не закрываются вообще.
  • Ошибка сохранения в карточке клиента выводится в самый низ страницы — под лентой комментариев, за экраном от кнопки, которая упала.
  • Подсказка на карточке клиента отправляет включать гостевую ссылку через меню «⋯» — кнопку оттуда давно вынесли наружу. Инструкция врёт.
  • Ни одного обработчика клавиатуры и ни одной ARIA-роли в самом большом экране панели.
Принципы

Шесть правил, из которых собирается новая панель

Вы работаете в ней один и каждый день. Значит, оптимизируем не обучаемость новичка, а скорость и надёжность привычной руки: меньше поверхностей, устойчивые места, никаких сюрпризов.

1. Раздел — это работа, а не таблица

Названия совпадают с тем, что вы делаете и говорите вслух. «Маршруты», «Каталог», «Программы» — а не «Route Stops», «Resources Library», «Multi-Day Builder». Название пилюли = заголовок экрана = слово, которым вы это зовёте.

2. Один объект — одна карточка, вкладки внутри

Маршрут: Точки · Тексты · Вопросы · Фото · Публикация. Место: Текст · Данные · Где используется. Клиент: Программа и деньги · Анкета · История. Вопрос «где это редактируется» перестаёт существовать: там же, где сам объект.

3. Главный экран отвечает на вопрос «что делать», а не «как дела»

Очередь дел с глаголами и сроками наверху, цифры — внизу и мелко. Каждая строка — один клик до действия.

4. Состояние считается из фактов, а не выставляется руками

Анкета пришла, программа сохранена, ссылка включена, деньги получены — всё это уже есть в базе. «Следующий шаг» выводится из них. Ручная стадия остаётся, но как исключение, а не как единственный источник правды.

5. Один словарь и одна механика сохранения на всю панель

Состояния: Черновик → На проверке → На сайте (и «Скрыт» как отдельный флаг). Сохранение: черновик пишется сам, выкладка — всегда явная кнопка. Один и тот же индикатор «не сохранено» везде. Кнопка называется «Опубликовать» — сообщение говорит «Опубликовано».

6. Действие живёт рядом с объектом, а разрушительное — за подтверждением

Сохранение не в километре над полем. Удаление — с подтверждением и отменой на 10 секунд. Уход со страницы с несохранённым — вопрос.

Слово «Настройки» пришлось убрать

В первой версии я сложил в «Настройки» четыре вещи: оговорки печатной программы, матрицу ставок, подключения и бота. Первые две туда не годятся: они не настраивают панель, они определяют саму программу — что напечатается в документе гостя и по какой цене. Это часть продукта, а не служебный ящик.

Поэтому «Ставки» и «Что печатается в программе» переезжают в раздел «Программы» соседними вкладками к списку. А то, что осталось — сервисы и бот, — честно называется «Подключения».

У каждого такого блока написано, откуда данные

Отдельной строкой в каждой вкладке, потому что иначе непонятно, где источник правды и что произойдёт при правке мимо панели:

БлокИсточник
Оговорки программы Airtable, таблица Document Settings · поля Key · Title · Text · Enabled · Order · Kind. Недоступность таблицы печать не роняет
Базовые ставки Airtable, таблица Pricing · ключ строки Rate Key, ремарка клиенту — поле Notes. Ключи не переименовывать: по ним расчёт находит строку
Расчёт внутри тура Airtable, Routes → Pricing Data, одно поле JSON
Ключи провайдеров Airtable, таблица Integrations, зашифрованы мастер-ключом INTEGRATIONS_SECRET
Базовые сервисы и бот Только переменные окружения Vercel. Панель показывает, но не меняет
Реквизиты бренда Нигде в базе. Имя гида, почта, домен, метка бренда, эйлайн обложки PDF и названия типов дня лежат в коде. Менять — только правкой кода и деплоем
Реквизиты бренда — единственное, что нельзя поправить самому. Если это мешает, выношу их в таблицу вместе с оговорками.

Программа и маршрут — разные задачи в одной таблице

Это место, где путается не только панель, но и модель данных. В таблице Routes лежат вперемешку публичные страницы сайта (intercity, city-tour) и туры, собранные в конструкторе под конкретного гостя. Одна и та же запись может быть и тем и другим: программа из конструктора выходит на /multi-day/<slug>, как только статус становится Published.

Разводить их надо не по таблице, а по задаче:

  • Программа — документ для гостя. Конкретные даты, состав группы, цена, ссылка, PDF. Живёт в разделе «Программы» и в карточке клиента.
  • Маршрут — страница сайта, которая приводит клиентов. Точки, тексты, вопросы, фото. Живёт в разделе «Маршруты».
  • Шаблон — программа без клиента и без дат, из которой собираются новые. Сегодня такого понятия нет вовсе: «Золотой маршрут» лежит в одной куче с турами клиентов и отличается только тем, что вы помните, какой из них чей.

Переход между ролями — один явный флажок в карточке программы: «Опубликовать на сайте». После него программа появляется ещё и в «Маршрутах», в группе «Многодневные». Действие видно с обеих сторон, а не выводится из значения поля Status, которое вдобавок однажды уже молча ломалось.

И одна новая вещь: поиск по всему на ⌘K

Это самый дешёвый и самый сильный ответ на «не помню, где что редактируется». Печатаете «хаконе» — получаете маршрут Хаконе с прямыми ссылками в его вкладки, места с этим словом, клиентов, у которых Хаконе стоит в программе, и действие «поставить в программу». Структуру можно вообще не запоминать: достаточно помнить название вещи.

Доработка

Четыре сквозные вещи, которые я сначала недодумал

«Сайт» был разделом-свалкой и разошёлся надвое

В первой версии я собрал туда общий FAQ и журнал по принципу «всё публичное, что не маршрут» — определение через отрицание, ровно та ошибка, за которую я ругаю старую панель. Раздел разошёлся на два честных: «FAQ» — все вопросы и ответы, общие и по маршрутам, в одном редакторе; «Журнал» — статьи и очередь агента, отдельная работа с отдельным ритмом.

Редакторов вопросов два, и хуже работает тот, что важнее

Общий FAQ (/admin/faq) — лучший экран в панели. Он знает то, чего не знает таблица: сколько абзацев получится из ответа, попадёт ли вопрос в разметку для поисковиков, что будет при публикации без ответа. Он защищает якорь от правки, потому что якорь — часть публичного адреса. Он сохраняет только изменённое. У него честный словарь состояний: «На сайте», «Черновик», «Скрыт».

Вопросы маршрута устроены иначе: JSON-строка в одном поле, редактируемая другим экраном. Без статусов, без счётчика абзацев, без порядка, без подтверждения на удаление. Кнопка «Добавить вопрос» кладёт в ответ пробел — и получается опубликованный вопрос с пустым ответом внутри разметки. Ровно то, от чего общий редактор предостерегает отдельным предупреждением. А если JSON в поле окажется битым, редактор молча покажет «не заполнен» и следующим сохранением сотрёт данные.

Один редактор вопросов, две поверхности. Тот, который уже написан хорошо, — и есть эталон.

«Обновить кэш сайта» — общая кнопка, живущая на одном экране

Она сбрасывает кэш всего сайта, но стоит в шапке выбранного маршрута и читается как «обновить этот маршрут». Единственная во всей панели. При этом общий FAQ обходится без неё (его сохранение само сбрасывает нужный тег), журнал велит её нажать, но кнопки у себя не имеет, а публикация текста точки не сбрасывает кэш вообще — выложенное описание может не появиться на сайте до часа, и понять причину неоткуда.

Правильное место — шапка панели, рядом с поиском, с подписью «правки из Airtable появятся сразу». И сброс после каждой публикации, автоматически.

Агентских очередей три, и ни одной не видно с главной

Статьи от агента живут на экране «Журнал» — единственном, который вообще не использует общую оболочку. Точки, присланные POI-ботом, не собираются нигде: найти их можно, только зная название. Предложение английского имени от генератора показывается внутри карточки точки и исчезает навсегда при переходе к другой. Три разных механизма, три места, ноль общего вида.

Это одна работа: агент что-то сделал, нужна ваша вычитка. У неё есть свой блок на «Сегодня», между «Сейчас» и «Не горит» — не срочно, но и не фон.

Панель API: состояние и настройка — разные задачи

Панель внешних сервисов сделана заметно лучше остальных: шифрованный сейф с приоритетом переменных окружения, проверка с задержкой и текстом ошибки, каталог доступных моделей, отдельная песочница под новые сервисы. Ей мешают две вещи.

Первая — на главной странице стоит собственный дубль из трёх галочек, который проверяет не то же самое: OpenAI там считается рабочим по факту наличия переменной, а не по ответу сервиса. Отозванный, но не удалённый ключ на главной зелёный, а в панели API — «Ошибка». Дубль убирается, проверка остаётся одна, а её итог приходит одной строкой в «Не горит».

Вторая — защита обратна риску. «Стереть ключи» срабатывает сразу, без подтверждения, и разрешено даже тогда, когда сохранение запрещено: то есть можно уничтожить то, что отсюда уже не восстановить. Проверить ключ до сохранения нельзя — чтобы убедиться, что он рабочий, приходится сначала записать его в сейф. Свёрнутая карточка молча выбрасывает вставленный ключ. Всё три чинятся в первой волне.

Экраны

Что конкретно меняется

Сегодня

Пять-семь строк, каждая — глагол, объект, причина и одна кнопка. Слева — счётчик ожидания крупной антиквой, он же сигнал: красный, если просрочено. Ниже — «Не горит»: то, что копится в фоне и не срывает поездку. В самом низу — «Месяц» с воронкой и конверсией, для тех редких случаев, когда нужен именно отчёт.

Карточка клиента

Наверху — полоса сделки: заявка · анкета · программа · отправлено гостю · оплата · поездка, с датами под узлами. Под ней одной строкой — следующий шаг и кнопка, которая его делает. Дальше — «Программа и деньги»: название тура, итого, на человека, дней с гидом, состояние гостевой ссылки с кнопкой «Включить», PDF. Всё то, ради чего сейчас приходится уходить в конструктор и на отдельный экран в новой вкладке.

Конструктор

Сейчас это одно бесконечное полотно: на четырнадцатидневном туре — четырнадцать карточек в полную ширину, около трёхсот органов управления, никакой навигации кроме прокрутки и никакого признака, что день закончен. Предлагается три зоны: полоса дней сверху (та же графика, что у полосы сделки, с пометкой пустых дней), узкий навигатор дней слева, один день крупно в центре и контекст справа — гость и цена этого дня. Число гостей и даты подтягиваются из анкеты, а не вбиваются заново.

Маршрут

Слева — список маршрутов по типам с индикатором заполненности 4/4. Справа — одна карточка с пятью вкладками. Пять экранов схлопываются в один объект.

Порядок групп — Токио → Выездные → Многодневные, как в каноне типов туров. Сегодня он случайный: сайдбар «Остановок» группирует записи по сырому значению поля (intercity, city-tour, other) и рисует группы в том порядке, в каком типы встретились в выдаче. Заголовки групп — те же сырые слаги, заглавными.

Отдельная ловушка: Такао и Митакэ лежат по адресу /city-tour/, а по типу тура относятся к выездным — так записано в каноне. Пока группировка идёт по префиксу URL, они всегда будут падать не в ту группу. Группировать надо по типу тура, и тип должен быть выбором из списка, а не строкой, которую можно напечатать: сейчас поле ввода с подсказками, и опечатка навсегда заводит новую группу в сайдбаре.

Страницы форматов передвижения — /city-tour/charter, /private, /public и их выездные двойники — маршрутами не являются: это страницы про транспорт. Им нужна либо своя группа «Форматы», либо место в разделе «Сайт». Оставлять их вперемешку с турами — тот же тип ошибки, что и всё остальное здесь.

Каталог

Фасеты слева включают не только типы, но и «что не в порядке»: без описания, без ссылки, черновики, событие закончилось. Карточка записи получает вкладку «Где используется» и счётчик «в 3 маршрутах» прямо в списке. Это меняет отношение к работе: видно, что́ сломается, если оставить поле пустым.

Границы

Что в этой панели трогать не надо

  • Палитру. Тёплая монохромная база с терракотовым акцентом и золотым первичным действием — уже фирменная и хорошо работает в обеих темах. В прототипе использованы ровно те же --adm-* переменные, ни одного нового цвета.
  • Серверные предохранители сохранения конструктора и автобэкап программы. Они появились после реального инцидента с перезаписью тура пустым состоянием. Менять надо подачу их отказов на экране, а не сами правила.
  • Канон текстов: транслитерация («Хаконе», не «Хаконэ»), несклоняемость топонимов, шесть разрешённых формулировок транспорта, запрет выносить длительность тура в документы. Прототип им следует.
  • Авторизацию в src/proxy.ts — отдельная история с отдельной ценой ошибки. Любая правка оболочки не должна её касаться.
Кликабельный прототип
