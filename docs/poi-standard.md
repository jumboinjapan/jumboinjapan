# Эталон записи POI

База лежит в основе проекта. Всё остальное — программы, печать, сайт, боты —
читает её и не может быть лучше неё. Поэтому эталон записан здесь, а мерка
к нему исполняется: `npm run poi:score`.

Документ отвечает на один вопрос: **что значит «запись готова».**

## Почему эталон, а не список ошибок

Два дня работы над приёмом свелись к разбору ошибок поштучно — пустое
описание, текст в неверном поле, имя без английской пары, выдуманный текст,
кафе вместо холмов. Каждая находка была отклонением от нормы, которую никто
не сформулировал. Пока нормы нет, ошибки находятся случайно и по одной;
когда она есть, отклонения считаются одной командой.

## Три класса записей — и почему их нельзя мерить одной меркой

Первая же попытка посчитать «записи без описания» дала 29 и оказалась
бессмысленной: шесть из них — зоны Этиго-Цумари, у которых описания и не
должно быть. Мерка, не различающая классы, врёт в обе стороны: ругает
исправное и молчит про сломанное.

| Класс | Признак | Зачем существует |
|---|---|---|
| **Служебный** | `Is System` | Заглушки конвейера: аэропорт, заселение, переезд. В программах видны, гостю как достопримечательность не показываются |
| **Родительский** | есть дети, нет `Google Place ID` **или** координат | Держит связку: «Дом-проект», «Холмы Биэй», «Остров Тэсима». Координат нет намеренно — они у детей |
| **Обычный** | всё остальное | Место, которое можно поставить в программу и показать гостю |

Родительская запись без координат — не дефект, а решение. Родительская
запись с координатами, отобранными у ребёнка, — дефект.

## Эталон обычной записи

### Тождество — кто это

| Поле | Требование | Почему |
|---|---|---|
| `POI Name (RU)` | обязательно | Запись без имени не заводится |
| `POI Name (EN)` | обязательно | Ключ поиска в Google и во внешних источниках |
| `Name (JA)` | желательно | **Сильнейший ключ сверки дублей.** Латиница у нас и у источника расходится всегда, японское написание почти никогда. Берётся из Wikidata (CC0) — хранить можно вечно, в отличие от содержимого Google |
| `Google Place ID` | обязательно | Без него ежемесячный прогон координат запись ПРОПУСКАЕТ, а статус «Работает» проставить нечем. Хранится бессрочно |
| `Wikidata QID` | желательно | Бесплатный и вечный источник фактов и японского имени |

Имена RU и EN обязаны быть **парой по смыслу**: если английское несёт
префикс («Art House Project: Kinza»), русское обязано нести его тоже.
Гость видит имя в программе без контекста.

### Место — где это

| Поле | Требование | Почему |
|---|---|---|
| `Site City` | из справочника `KNOWN_CITIES` | Отбор и группировка |
| `Prefecture (RU)` / `(EN)` | из таблицы 47 префектур | Ответ внешнего источника приводится к нашим значениям или отвергается. Записывать «как есть» нельзя: Google при `languageCode=en` иногда отдаёт японское название |
| `Latitude` / `Longitude` | обязательно, только парой | Гейт дублей решает по расстоянию. Без координат он работает вслепую |
| `Coords Checked At` | не старше 30 дней | Условия Maps Platform: `place_id` бессрочно, остальное — тридцать дней. Координата у нас не запись, а кэш |
| `Parent POI` | если объект внутри другого | Связность: павильон храма, дом арт-проекта, работа на острове |

### Состояние — работает ли

| Поле | Требование | Почему |
|---|---|---|
| `Operating Status` | обязательно | Закрытую точку в программу ставить нельзя. Пустое значение — не «работает», а «не проверено» |
| `Season Window` | обязательно при статусе «Сезонный» | Без окна программа не сможет свериться с датами тура. Формат `ММ-ДД–ММ-ДД` без года: сезон повторяется ежегодно |

### Содержание — зачем туда ехать

| Поле | Требование | Почему |
|---|---|---|
| `POI Category (RU)` / `(EN)` | 1–3 из канона | По ним точка подбирается под интересы гостя |
| `Description Approved (RU)` | обязательно | То, что видит гость |
| `Description Approved (EN)` | парой к русскому | Половина записи — половина карточки |
| `Text Source` | обязательно | Откуда взят текст. Без этого нельзя отличить исследование от вымысла — а отличать пришлось |
| `Facts (JSON)` | желательно, включая **значимость** | Текст, написанный по одним лишь часам и адресу, выйдет про часы и адрес. «Чем важно» — такой же факт, как адрес, и собирать его надо намеренно |
| `Working Hours` | со ссылкой на источник | Изменчивое поле: публиковать без подтверждения нельзя |
| `Website` | со схемой `http(s)` | Иначе Airtable отвергнет значение |

## Эталон родительской записи

Обязательно: имя RU и EN парой, `Site City`, хотя бы один ребёнок.
Желательно: описание — оно объясняет, что объединяет детей.
**Не требуется:** координаты, `Google Place ID`, `Operating Status`.

Родитель без детей — дефект: пустая ветка в дереве.

## Эталон служебной записи

Обязательно: имя RU, `Is System`, пояснение в `Notes`.
Не требуется: ничего из содержания. Гостю как место не показывается.

## Гигиена, общая для всех классов

- Канонические написания топонимов (`npm run check:canon`)
- Японские топонимы не склоняются
- Один `place_id` — один POI
- Текст лежит в своём поле: заполненный `Description (RU)` при пустом
  `Approved` означает, что редактор видит пустоту, а гость — текст

## Как мерить

```bash
npm run poi:score            # сводка: дистанция до эталона по классам
npm run poi:score -- --list  # поимённо, что кому не хватает
npm run poi:score -- --city kyoto
```

Мерка не падает: это не проверка на ошибку, а расстояние до цели.
Падают `check:canon` и `check:poi` — там нарушения, а не неполнота.
