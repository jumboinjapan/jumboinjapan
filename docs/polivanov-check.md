# Проверка транслитерации и рост базы

`npm run check:polivanov` выполняет две разные проверки:

1. Ворота регрессии на неизменном `tests/fixtures/poi-names.json`: 394 имени,
   на которых был установлен порог 45%. Порог и файл не изменены. Пустой
   контрольный корпус или результат ниже порога останавливают проверку.
2. Диагностика текущих имён Airtable: число совпадений, расхождений и имён,
   переданных человеку. Результат ниже 45% выводит предупреждение для
   редакторской сверки, но не объявляется регрессией неизменного кода.

`--show N` показывает примеры расхождений текущего корпуса. `--fixture PATH`
явно заменяет контрольный корпус на указанный файл и не обращается к базе;
так можно воспроизвести отказ. Пустой файл данных не проходит ворота.
Без ключа или при недоступной сети сохраняется прежний явно объявленный
переход на снимок: это не доказательство чтения живой базы.

Причина разделения установлена 25.09.2026 на `main` / `bbf5a31`: неизменный
транслитератор даёт 151 совпадение из 286 автоматически обработанных имён
исходного корпуса (52,80%), но 403 из 896 в выросшей базе (44,98%). Сравнение
разных составов ошибочно останавливало сборку как регрессию кода. Порог не
снижен, имена и транслитератор не исправлялись ради прохождения проверки.

Ограничение: старый контрольный корпус не покрывает новые классы названий.
Их следует добавлять в адресные тесты `tests/polivanov.mjs` при подтверждённой
ошибке транслитератора. Редакторские расхождения не исправляются автоматически.
