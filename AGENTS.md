## 4. Проверка

```bash
npm ci          # именно ci: ловит рассинхрон package-lock
npm run verify  # lint → typecheck → тесты → типографика → контракты
                # документации → длина текстов → каноны → Поливанов →
                # целостность POI → токены → картинки → build
```

`npm test` — состав наборов смотреть в `package.json`, скрипт `test`. Число файлов и проверок здесь не дублируется: оно меняется чаще, чем этот документ.

`npm run verify` **не гарантированно офлайн**. Несколько стадий сами загружают `.env.local`;
если в нём есть Airtable-токен, они выполняют read-only-запросы к живой базе даже тогда,
когда агент не экспортировал переменные в shell. Постоянное исключение из правила «чтение с
ключами — по отдельному разрешению» (решение владельца 07.09.2026,
`docs/poi-intake/pilot-owner-decisions-2026-09-06.md` § III): read-only стадии `npm run verify`
— целиком или любую стадию по отдельности — агент запускает без отдельного разрешения при
условиях: только GET, без `--write`/`--apply`, лог в `tmp/`, факт живого чтения и список
прочитавших базу стадий названы в отчёте. Всё остальное чтение с ключами — экспорты,
коллектор, разовые GET, Google, модель — по-прежнему по отдельному разрешению на каждый
случай. Переименовывать или править `.env.local` ради «офлайн»-прогона запрещено; офлайн-набор
из `docs/poi-intake/agent-maintenance-guide.md` § 10 не выдаётся за полный `verify`.

Без ключей живые Airtable-проверки пропускают свою часть, говорят об этом вслух и не делают
сетевых запросов. Пропуск без ключей — штатный локальный режим, а не провал. С настроенными
ключами недоступная сеть — **настоящий отказ** соответствующей проверки: «ключа нет» и «база
не отвечает» обязаны различаться. Единственное известное исключение — `check:polivanov`
(`scripts/check-polivanov.mjs`): при ошибке сети с ключом он сам переходит на снимок
`tests/fixtures/poi-names.json`, сообщает об этом в stdout и завершается с кодом 0. Такой
прогон не доказывает сверку с живой базой: если в выводе есть строка «База недоступна»,
результат стадии нужно называть сверкой по снимку, а не «зелёным» живым чтением.

CI выполняет те же стадии и в том же порядке, отдельными шагами после `npm ci`, на Node 22 и 24; равенство состава и порядка стережёт `npm run check:docs`. По решению III‑2 (07.09.2026) CI — каноническое место непрерывного `verify`: секреты `AIRTABLE_READONLY_TOKEN` (только чтение) и `AIRTABLE_BASE_ID` передаются только шести читающим стадиям (`check:copy`, `check:canon`, `check:polivanov`, `check:poi`, `check:images`, `build`), они делают те же read-only GET, что и локально; `npm test` секретов не получает и остаётся офлайн (локально — `env -u AIRTABLE_TOKEN -u AIRTABLE_BASE_ID npm test`, если переменные экспортированы в shell). Лог Actions служит доказательством условия «один непрерывный `verify`». Без секретов (форк) действует режим пропуска без ключей.

Отдельные шаги: `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`.

## 5. Опасные команды и области

Ничего из списка не делать без полномочий владельца. Постоянное разрешение § VI на POI-черновики уже даёт полномочия на соответствующий запуск импортёра; повторно спрашивать не нужно.

| Опасно | Почему |
|---|---|
| `git add -A` | В корне лежит `_to_delete/` на сотни мегабайт; GitHub отклонит пуш. Файлы перечислять поимённо |
| `git push --force`, перезапись `main` | История общая |
| Любой запуск импортёра с `--write` | Пишет в боевой Airtable |
| `scripts/browser/poi-screen-smoke.js` | Гоняется по живой панели и правит живые записи. Возврат сверяется, но следить обязательно |
| Удаление редиректов в `next.config.ts` | Ломает поисковую выдачу по старым адресам |
| Смена канонических URL, `sitemap`, схемы `schema.org` | То же самое |
| Правка `src/proxy.ts` | Здесь живёт авторизация админки. Next 16 молча игнорирует `middleware.ts` — из-за этого админка однажды простояла публично открытой. Изменения — только через ветку и preview-деплой |
| Переименование полей и статусов Airtable | Ломает и сайт, и импортёр |
| Правка `src/lib/airtable-schema.ts` | Единственное место, где живут идентификаторы таблиц |

Отдельно: **отсутствие настройки не должно ослаблять проверку**. Незаданная переменная закрывает функциональность, а не открывает её. Именно так был устроен дефект в Telegram-вебхуке (`src/lib/telegram-owner-gate.ts` — правило и тест).

## 7. Что не делать с текстами

Публичные русские тексты — не место для машинного тона. Ни «уникальный незабываемый опыт», ни калек с английского («день раскрывается», «мягкий старт»), ни императива («идите», «попробуйте»). Пишем как гид, который объясняет, почему маршрут устроен именно так: логистика, сезон, время в пути, что реально успеть.

Лимиты длины — в `src/lib/copy-limits.ts`, проверяются `npm run check:copy`.

## 8. Известный долг

Не сюрпризы, а записанные вещи. Трогать — отдельными задачами.

- **Импортёр Japan Travel не находит событий.** `parseIndexCandidates()` читает только `Event` JSON-LD, которого на индексной странице больше нет: данные уехали в hydration payload. Известно с 2026-07-03. Разбирается в отдельной ветке — не чинить попутно.
- **Предупреждения компилятора React** — `set-state-in-effect`, `purity`, `static-components`. Понижены до warn в `eslint.config.mjs` с пояснением. Чинятся вместе с разделением экранов, а не вперемешку.
- **Модули, которые пора делить**: `MultiDayBuilderWorkspace.tsx` (3258 строк), `AdminResourcesWorkspace.tsx` (1640), `japantravel-events.ts` (1467), `AdminOperationsConsole.tsx` (1435), `TouristProfileForm.tsx` (1395), `resources.ts` (1051).
- **`npm run poi:collect`, `poi:gaps`, `poi:sources`** — ручные отчётные инструменты из `scripts/poi-portals/` (каталог в репозитории с 2026-08). В `verify` им не место: они ходят в сеть за содержимым порталов и печатают отчёт, а не выносят вердикт. `poi:gaps` читает локальный снимок базы, по умолчанию `tmp/poi-base.json`, и путь переопределяется флагом `--base`.
- **`npm run check:polivanov-wd`** ходит в SPARQL Wikidata. В `verify` не подключён намеренно: внешний сервис не должен ронять ворота.

переиспользовать, но базы, таблицы, настройки, реестры, разрешения, журналы и документация у
них должны быть разными. Не добавлять гостиничные файлы или проверки в POI-коммит и не считать
POI-разрешение полномочием для гостиничного процесса.

`docs/poi-intake/review-workspace.md`. Обсуждения не подменяют проверки Intake и не
дают разрешения на публикацию. Само появление комментария агента не запускает.

## Учёт расходов

Решение владельца 09.09.2026: «Давай считать только фактические расходы,
потенциальные можно игнорировать» (решения владельца, § VIII).
Расходом считать только сумму, подтверждённую биллингом провайдера, счётом
или платёжным документом, с указанием периода и источника. Начисление за
использование и списание с карты различать; к POI относить только подтверждённую
долю. Без данных биллинга писать «фактические расходы не подтверждены», а не $0.
Число запросов, денежный потолок и произведение запросов на тариф не являются
фактическими расходами. Потенциальные суммы в обычные отчёты владельцу не включать.
