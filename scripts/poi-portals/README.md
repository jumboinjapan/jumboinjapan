# Коллектор POI с порталов Японии

Прототип. Полное обоснование, разбор источников и дорожная карта —
в `docs/poi-portal-collector.md`.

## Установка

```bash
npm i csv-parse
```

## Запуск

```bash
# один портал, отчёт в файл
node scripts/poi-portals/collect-pois.mjs --portal bodik-osaka-tourism --out tmp/osaka.json

# обкатка на первых 300 записях
node scripts/poi-portals/collect-pois.mjs --portal bodik-kyoto-tourism --limit 300

# сверка с текущей базой POI на дубли
node scripts/poi-portals/collect-pois.mjs --portal bodik-osaka-tourism --existing tmp/poi-dump.json

# мониторинг: что изменилось у источника с прошлого прогона
node scripts/poi-portals/collect-pois.mjs --portal bodik-osaka-tourism --monitor tmp/osaka.json
```

Формат `--existing`: массив объектов
`{ poiId, nameRu, nameEn, nameJa?, lat?, lon?, sourceKey? }`.

## Правила

**Ничего не пишем по умолчанию.** Без флагов скрипт только считает и
показывает. Репетиция против живой базы — `--preview`, запись — `--apply`.

Имена флагов выбраны так, чтобы **у них не было общего корня**. Прежние
`--write` и `--dry-write` этим правилом пренебрегали: безопасный флаг
содержал опасный подстрокой, и обрезанная при копировании команда молча
превращала репетицию в запись в прод. Опечатка обязана падать в безопасную
сторону, а не повышать права. Старые имена ещё принимаются, но печатают
предупреждение.

**Запись разблокирована** (август 2026). Прежде `--write` намеренно падал
с ошибкой, потому что в схеме POI не было `Source Key`, `Latitude`,
`Longitude` — без них повторный прогон создавал дубли, которые нечем
вычистить. Поля добавлены, запись идёт только через `ingestPoiBatch`,
то есть через тот же гейт, что и остальные пути приёма.

**Координаты засыпаны на три четверти** (9 августа 2026). Было 33 записи
из 428, стало **307 из 417 несистемных**. Два прогона:

- `npm run backfill:coords` — Wikidata, дала 128. Бесплатно, хранить можно
  вечно (CC0), заодно проставила `Wikidata QID` и `Name (JA)`.
- `npm run backfill:coords-google` — Google Places, дала ещё 146.

Геометрическая половина гейта — самая сильная, та, что опровергает
совпадение имён при двух километрах между точками, — теперь работает против
74% базы, а не против нуля.

**У координат из Google срок годности.** Условия Maps Platform разрешают
хранить `place_id` бессрочно, остальное содержимое — тридцать дней. Поэтому
рядом с координатой лежит `Google Place ID`, а `npm run refresh:coords`
раз в месяц перечитывает координаты по нему. Не запускать этот прогон —
значит хранить чужие данные дольше разрешённого и называть это иначе.

`Name (JA)` здесь важнее координат: имена на латинице у нас и у портала
расходятся всегда, японские — почти никогда, и сверка по ним куда надёжнее.

**Источник с `licence.commercial !== true` пропускается автоматически.**
Проприетарные порталы (osaka-info, dive-hiroshima, hakone.or.jp) лежат
в реестре как проверенные, но в прогон не берутся, пока не решён вопрос прав.

## Добавление портала

Только запись в `registry.mjs`. Поля `verified.at` и `licence` обязательны:
непроверенный источник в реестр не попадает.

Если источник — CSV в стандарте `自治体標準オープンデータセット`, адаптер
`opendata-csv` подхватит его без правок кода: колонки читаются через
таблицу алиасов с нормализацией ширины символов. Проверено на двух
несовпадающих схемах (Осака 58 колонок, Киото 32).

Для нового класса источников — новый адаптер в `lib/`, регистрация
в `ADAPTERS` внутри `collect-pois.mjs`.

## Что в отчёте

- `totals.autoImportable` — сколько прошло все четыре условия автоимпорта
- `totals.needsLlmCategory` — очередь на ступень 1 каскада, прямая оценка счёта
- `totals.volatileFieldsUnverified` — записи, чьи часы и цены публиковать нельзя
- `rejectReasons` — причины отбраковки со счётчиками
- `aiCost` — стоимость прогона по фактическому корпусу
- `all` — полный список решений по каждой записи, не только примеры

Последнее важно: на вопрос «почему эта точка не прошла» надо уметь
отвечать без перезапуска прогона.
